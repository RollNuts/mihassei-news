# veripsa.com｜サイト刷新後の検索インデックス点検

**確認日：2026-11-03（JST）**  
対象：現在の「未発生新聞」。旧タイトル・旧URLの検索キャッシュを整理し、現在の創作ニュースへ適切に検索流入するようにするための、無料の手順。

## 見つかったこと

公開検索結果に、過去の「Veripsa Core」（GitHubのAIエージェント向けPRサービス）を説明するページや検索スニペットが残っている。検索結果はクロール後に更新されるため、**検索結果に古い文面があることと、現在のサイトが古いページを配信していることは違う**。両方を混同しない。

現行サイトは独自ドメイン上で「未発生新聞」として運用し、`https://veripsa.com/sitemap.xml` を生成している。検索登録と掲載順位は保証できず、アクセス数（匿名ブラウザ）とは別の観測項目。

## 優先する確認順（追加料金なし）

1. Google Search Console の **`veripsa.com` ドメインプロパティ**で所有権と最新の「ページ」レポートを確認する。作成済みなら重複登録しない。
2. **URL検査**に `https://veripsa.com/` を入力し、ライブテストで「未発生新聞」のタイトル・canonicalを返すか確認。クロール可能なら「インデックス登録をリクエスト」。頻繁な再リクエストでは速くならない。
3. 「サイトマップ」に `https://veripsa.com/sitemap.xml` を登録・確認。失敗時は **HTTPステータス、DNS、クローラが取得した日時**を区別する（古い失敗履歴だけで本番障害と断定しない）。
4. 実際に公開済みの代表記事2〜3件について URL 検査。見出し、画像、canonical、現実の初公開日を確認。ホーム、アーカイブ、記事が内部リンクでつながっているか確認。
5. 旧サービスで使われていた `/solutions/`、`/blog/`、`/docs/` などは、まず**現在の HTTP 応答**を確認。存在しない旧URLが適切な **404/410** なら、基本的には再クロールによる自然な除外を待つ。無関係な旧記事を全部ホームにリダイレクトしない。現行の必要なURLは削除しない。
6. 緊急に古いスニペットを隠す必要がある**個別URLだけ** Search Console の削除ツールを検討する。削除ツールは一時的で約6か月。ホーム全体や新規記事を丸ごと削除対象にしない。
7. 後日、検索パフォーマンスの「表示回数」「クリック数」「CTR」「検索語」を確認。**匿名ブラウザ数・PV・人間の実人数とは混同しない**。数日〜数週間は履歴が足りない可能性がある。

## 読み取り専用の継続チェック

- GitHub Actions の **Verify live article delivery and SEO** が、公開 `/build-revision.txt` と対象SHAの一致、canonical、サイトマップ、新着記事とOGP画像を検査。
- **Public audience API health** はAPIの応答を検査するが、検索エンジンへの登録を保証しない。
- 旧URLを再利用する予定ができた場合は、404ルールをむやみに固定せず、現行の公開構造と検索意図に照らして見直す。

## サイトマップ成功後の確認（2026-11-03）

Search Console のサイトマップが「成功」でも、全記事が検索登録されたことを意味しない。
URL 検査の**ライブテスト**で「URL は Google に登録できます」と表示された場合、
そのページは登録可能であり、**実際の登録状況**は「Google インデックス」タブで確認する。
未登録ならトップページと重要記事数本だけ「インデックス登録をリクエスト」する。
「再リクエスト」はライブテストの再実行であり、登録要求と混同しない。
繰り返し送信してもクロールを速められない。大量の記事は既に送信済みのサイトマップで通知する。

### 記事増加時の自動SEO監査

CI はサイト生成後に \`python3 scripts/audit_search_index.py\` を実行する。
この監査はサイトマップ全URLについて、対応するHTML、canonical、noindex、
タイトル、概要、OG画像、構造化データ、記事の実際の公開・更新日時、
トップからHTMLリンクで到達できることを確認する。加えて、サイト内リンクの
リンク先ファイル・ページ内アンカーが本当に存在するかを検証する。
無料、読み取り専用で
Google Search Console の権限やAPIキーは必要としない。

**注意：** CIでの成功はGoogleへのインデックス登録成功を保証しない。
検索パフォーマンスやGoogleが選んだ正規URLはSearch Consoleで確認する。
