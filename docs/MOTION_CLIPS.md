# 未発生新聞：軽量動画（任意・追加費用0円）

承認済みの生成JPEGを、**12秒・24fps・3カットの無音ニュース映像**に編集する仕組みです。全景→注目箇所→引きの順に構図を切り替え、パンやズームと短い字幕で記事の展開を伝えます。処理は無料のローカルCPUとFFmpegで行い、人物そのものを動かすAI動画生成や実際の報道映像ではありません。

## 読者への配信

- 記事ごとの動画は、**検証済みMP4が存在する場合だけ**ネイティブHTML `<video>` で表示。動画がない記事は従来の写真／SVGのまま。
- **記事ページは手動再生・静止画posterあり・音声なし**。タップして見たい読者だけ再生します。
- トップは**1つのプレイヤーと最大3本の選抜候補**です。新しい検証済み動画を優先し、候補の実際の記事公開日・見出しから明示的に切り替えられます。ループや時刻で視聴中の記事を勝手に変更しません。
- 次回ページを開くときは、まだ再生していない候補を優先します。すべて再生済みなら最も前に再生した候補を表示します。ブラウザ内に最大12件の動画キーだけを保存し、外部送信はしません。保存が使えなくても最新動画と手動切替は動作します。
- 画面内にある間だけ無音プレビューを再生し、画面外やタブ非表示では停止します。読者の手動停止、動きを減らす設定、データ節約設定を尊重します。停止中に候補を切り替えても自動再生せず、ブラウザが自動再生を拒否した場合も手動で再生できます。
- 記事一覧のカードは静止画のまま。動画がある場合は実際の長さを示す小さなラベルだけを付け、一覧の動画ファイルは読み込みません。
- OGP／RSSはこれまでの軽いJPEG／PNGを使用。記事URL・canonical・サイトマップも変えません。
- 実際の動画がある記事だけ `VideoObject` に公開日時・MP4・サムネイル・動画の長さを記録。検索結果での動画表示は保証されません。

## カットと字幕

新しい動画は、全景を見せるカット、注目箇所へ寄るカット、再び引くカットの3つで構成します。写真の中の人物や小道具は静止したままです。記事の状況と合う写真だけを使い、構図を変えても主役やオチを見失わないか確認します。

字幕は `content/broadcasts.json` に記事slugと3つの短い文を明示し、ブラウザで `video.currentTime` に合わせて切り替えます。一時停止・シーク・ループでも動画と同じ位置を示します。字幕はMP4に焼き込まないため、字幕だけの修正は次の静的ビルドで反映でき、動画の再生成や画像・動画の指紋の変更は不要です。

新作の選抜は発行担当が行い、映像で具体的な場面と笑いを伝えられる記事だけに `broadcast_feature: true` を指定します。既存の目安は週1〜2本以下で、採用ノルマは設けません。同じ記事の字幕を `version: 1` の `stories[slug]` に用意し、現在の `article_sha256` と、本文に実際にある「状況→行動→オチ」の3つの `cues` を記録します。`at` は順に **0・4・8秒**、各 `label` は **1〜12文字**、`text` は **1〜40文字**です。字幕のために別の出来事や発言を足しません。

記事を改稿した担当は、本文と3字幕を読み直し、必要な文を直してから現在の記事指紋を記録します。指紋だけの付け替えで古い字幕を有効化しません。新しい動画の生成と現在の12秒形式（`motion_style_version: 3`）の配信には、現在の記事・JPEGに対する実際の目視合格記録と、有効な3字幕の両方が必要です。未検品を合格扱いせず、足りない場合も記事は安全な静止画で公開を続けます。

同じ検証済み字幕からWebVTTも生成し、ネイティブ全画面では字幕トラックを表示します。通常のページ内再生ではHTML字幕だけを表示し、二重に重ねません。候補を切り替えると映像・字幕・記事リンクを一緒に更新します。Picture-in-Pictureでの字幕表示は実機未確認です。

既存の**4秒・12fps**の検証済みクリップも引き続き配信できます。12秒形式の追加だけで旧動画を失効させず、各動画の長さに合う表示と構造化データを生成します。記事や元画像が変わった場合の整合性検査は、どちらの形式にも適用します。

## 使い方（既存のMac／ローカルPC）

まず、通常のGitHubリポジトリのコピーで実行します。**mac_scene_control の停止状態（OFF）を尊重**するため、止めている場合は再開を勝手に行いません。

~~~sh
# 候補の確認だけ。インストール・ネットワーク・新規ファイル作成なし
python3 scripts/motion_clips.py --limit 1

# 既存のffmpeg・ffprobeがある場合だけ、12秒の3カット映像を1本作る
python3 scripts/motion_clips.py --generate --limit 1
# または特定の記事だけ
python3 scripts/motion_clips.py --generate --slug ARTICLE-SLUG
~~~

**ffmpeg／ffprobeが入っていなければ停止するだけ**。自動インストール、brewの追加導入、API利用、有料GPUへの切り替えはしません。動画は `assets/clips/ARTICLE-SLUG.mp4` と `assets/clips/manifest.json` に保存されます。GitHubへの反映には、生成物の目視確認と通常のgitによる明示的なコミット・pushが必要です。スクリプトは勝手にpushしません。

## GitHub Actionsによる自動生成（無料、上限付き）

既存のMac画像生成スケジュールは変更せず、**検証済みJPEGがmainへ届いたとき**、`content/articles.json`・`content/visual_reviews.json`・`content/broadcasts.json`、動画生成処理・設定が更新されたときに `.github/workflows/auto-motion-clips.yml` が動きます。手動実行にも対応します。字幕の追加・修正で準備が整った未生成記事は生成へ進みますが、記事・画像に整合する現在の形式のMP4があれば、字幕修正だけで再生成しません。

GitHubのCPU画像生成は、正常に終わった公開用の処理で `--plan` を確認し、生成準備の整った候補（`pending > 0`）がある場合だけ動画ワークフローを明示起動します。botの画像pushや、画像未生成0件の毎時17分の確認からもready動画は1本ずつ進めます。OFF・生成済み・画像/検品/字幕待ちだけなら起動せず、plan失敗を0件と扱いません。新しい定期実行は追加せず、非公開プレビューや品質保留画像の再試行からも起動しません。

- GitHubの公開リポジトリで、通常の無料Ubuntuランナーを使用。新しい有料GPU・AI・動画生成API・サブスクリプションは使いません。使い切りランナーに限り、無償ffmpegを用意します。
- 対象は `broadcast_feature: true` と明示された記事だけ。新しい写真が増えただけで全記事を動画化しません。
- 起動時に、停止設定と、記事・画像・目視合格・3字幕がそろった未生成の選抜候補を標準ライブラリだけで確認します。OFFまたは候補0件なら、エンコーダーの準備・動画生成・pushは行いません。PRの検証では実エンコードの回帰テストを実行します。
- **1回の実行で動画を最大1本**。現在の演出形式で有効なクリップがあれば再生成しません。選定済み記事の旧形式は新形式への更新候補になりますが、新しいMP4が検証されるまでは有効な旧動画を保持します。画像に合わない古い映像は配信しません。
- `assets/clips/manifest.json` と検証済みMP4のみを、GitHubのbotが**通常の非強制push**で反映。更新競合時は最新mainを取り直して最大3回だけ再試行。
- 動画追加のbot pushでは通常のGitHub CIは自動発火しないため、**公開確認用ワークフローを明示的に起動**します。変更がなければ何もpushしません。
- Macローカル生成とは別の停止スイッチです。Macの `stopped.json` だけではGitHub上の動画生成は停止しません。

**いつでも停止:** `.github/motion-clips.json` の `"enabled": false` をmainへコミットするか、GitHub Actionsの `Free bounded article motion clips` をDisableしてください。再開は `"enabled": true`。停止中も既存の写真・記事・動画ファイルを削除しません。進行中の処理はmainの再確認とpush競合で停止し、緊急時はGitHub Actionsで実行中のジョブもキャンセルできます。

実行結果は [GitHub Actions](https://github.com/RollNuts/mihassei-news/actions/workflows/auto-motion-clips.yml) と、既存の [公開SEO検証](https://github.com/RollNuts/mihassei-news/actions/workflows/verify-public-photos.yml) で確認。GitHub上の自動生成結果とCloudflare本番への反映は**別々に検証**します。

## 待ち理由の確認と引き継ぎ

選抜記事を今回変更した発行・改稿担当と、残る未検品を扱うサイト担当は、既存枠で次の読み取り専用コマンドを使います。発行・改稿担当は今回分を確認し、残りはサイト担当へ渡します。このコマンドは生成・インストール・pushを行いません。

```bash
python3 scripts/publish_motion_clips.py --plan
```

JSONの `enabled` は自動生成の有効／無効、`pending` は生成準備が整った候補数、`stories` は選抜記事の `slug` と `state` です。OFFでは記事を走査せず `stories: []` を返すため、空の一覧を「未処理なし」と判断しません。

| state | 次に必要な作業 |
| --- | --- |
| `ready` | 既存の自動生成を待ち、実行結果と本番反映を別々に確認する。 |
| `current` | 現在の形式の有効なMP4がある。生成を重ねず、必要な本番確認へ進む。 |
| `image_required` | 対応する使用可能なJPEGが必要。品質保留も含むため、`python3 scripts/visual_review.py` で詳細を確認する。 |
| `visual_review_required` | 現在の記事・画像を実際に見て、合否と観察を正しく記録する。 |
| `captions_required` | 発行・改稿担当が本文と3字幕を照合し、不足・不整合を直す。 |

未解決分は既存の次枠メモまたは作業結果に「slug／待ち理由／次の作業と担当」を短く残します。画像の採用判断は[VISUAL_OPERATIONS.md](VISUAL_OPERATIONS.md)に従います。停止中の再開、根拠のない保留解除、対象の一括追加で待ちを消さず、新しいタスクや定期実行は増やしません。生成数や `current` だけで本番公開成功とは報告せず、内部の待ち理由を読者画面へ載せません。

## 容量と安全

| 項目 | 制限 |
| --- | --- |
| 新しい動画 | 12秒・3カット・24fps |
| 既存動画の互換性 | 4秒・12fpsの検証済みクリップを維持 |
| 解像度 | 640×360 |
| 形式 | H.264 MP4・音声なし |
| 動画1本 | 最大450KiB |
| 全クリップ合計 | 最大24MiB |
| 同時候補 | 1回最大2本 |
| クリップ登録 | 最大48本 |
| ローカル空き容量 | 12GiBを下回る場合は生成を中止 |

動画が記事の内容・承認済み画像・SHA-256と一致しない場合は、**動画を公開せず静止画へ戻す**。公開処理は許可したファイルのみコピーし、不明なMP4／古いmanifest／別記事の素材を除外。失敗時も記事と従来の写真は削除しません。

ローカル動画の作成を続けても上限に達したら新規生成を止めます。既存データを勝手に消して増産しません。実写で俳優や小道具が動く本格AI動画は別の重い生成処理が必要なので、この軽量機能とは区別しています。
