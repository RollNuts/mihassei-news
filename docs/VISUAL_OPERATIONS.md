# 表示と画像の品質を維持する運用

対象は公開新聞の読みやすさと画像の内容。公開数、画像生成数、PR数を品質の成果にしない。追加費用は0円。外部の有料AI・画像・動画API、有料GPU、追加クレジット、広告、新しい計測サービスを使わない。

## 担当と時間

時刻はすべて日本時間。タスクの実際の設定を正本とし、遅延があり得るため時刻差だけを排他制御とは扱わない。

| 担当 | 実行枠 | 作業範囲 |
| --- | --- | --- |
| サイト日次改善 | 月・火・木・金・土・日 02:15 | 新着画像の検品、表示・操作の不具合、前回未完了の修復 |
| 週次SEO・UX改善 | 水曜 02:15 | 同日のサイト日次枠を置き換え、全記事の画像・主要ページ・SEOを広く確認 |
| 題材探し・品質改善 | 毎日 05:45 | 前日の文章・画像を照合し、次の発行へ具体的な改善点を渡す |
| ニュース発行 | 毎日 07:30〜23:30の既存9枠 | 1枠1本の編集・公開。新しい画像の検品を含め、同一枠を重複発行しない |
| 週次編集・成長判断 | 月曜 10:10 | 記事の品質と、確認可能な読者反応を比較 |
| 推理連載／市場分析 | 火木土19:00／日19:00 | 各連載の内容と、その公開ページ・表紙・前後リンクを確認 |

Xの配信、停止済み漫画、MacのON/OFFと負荷保護は別管理。新聞側の都合で再開・上限変更をしない。

## 着手前と重複防止

1. 最新main、未統合PR、直近の該当タスク結果と実行中ジョブを読む。前の修正が未完了なら、その修正の状態確認・完了を先に進める。
2. 同じ記事・ファイルの作業が進行中なら重複PRを作らず、衝突しない課題を扱う。統合直前にも最新mainを取り直す。
3. 発行は予定枠のJST日付と時刻、既刊・PR・前回結果を照合する。遅延実行や再試行を新しい枠と見なさない。掲載済みの記事の初回公開日時を動かさない。
4. 同じ失敗を無条件で再試行せず、生成対象0件、品質保留、未検品、認証失敗、公開未反映を区別する。対象0件・idle・skippedを生成成功と報告しない。

## 画像の採用条件

`scripts/generated_photos.py` はJPEGの寸法・容量・SHA・記事指紋を検証する。これは絵の内容の合格判定ではない。

`scripts/visual_review.py` は `content/visual_reviews.json` の目視確認記録を照合する。`decision: accepted`、現在の `article_sha256` と `image_sha256`、タイムゾーン付きの実際の確認日時、具体的な観察メモが必要。生成されたJPEGが保存されただけでは公開採用しない。記事か画像が変われば過去の確認は失効する。

```bash
python3 scripts/visual_review.py
python3 scripts/build.py
```

一覧の `pending` は未検品、`rejected` は品質保留であり、失敗した生成ジョブとは別。発行担当は自分の新規画像と前枠から残った未検品画像を優先して最大3件確認し、残りは次枠またはサイト担当へ引き継ぐ。確認数を満たすために雑な合格を付けない。

発行・改稿の後は、CPU画像ジョブが非同期であることを踏まえて同じ実行内で検品まで確認する。既存ジョブが実行中なら重複起動せず最大15分待ち、未起動の場合だけ既存の無料CPUワークフローを最大1回実行する。未検品JPEGは再生成しない。完了後は最新mainを取得し、今回の記事と前枠の未検品を合計最大3件、下記の手順で実表示して確認する。合格記録の通常push後、公開記事・画像・OGP・RSSまで照合する。

時間切れ・画像を表示できない場合は検品完了と報告せず、slug・生成run ID・残る操作を次の既存枠へ引き継ぐ。新規タスクや頻度変更、追加クレジット、外部AI APIは増やさない。記事発行は継続する。保存された自動タスクの設定を確認できなかった場合、設定更新まで済んだとは記載しない。

実ファイルを表示し、対応する本文と次を照合する。

- 主役の人物・具体物が存在し、対象と個数・関係が合うか。牛とロバなら、区別できる2頭が必要。
- 行為と場所が記事の場面を伝えるか。謝罪メールを紙の証書、番組収録を無関係な会議室に置き換えない。
- 不自然な顔・手・融合した物体・宙に浮く物が、意図した創作と無関係に目立たないか。
- 小さいカードと記事の大きな表示で主題が見えるか。トリミングで対象や表紙文字が欠けないか。
- 代替文・クレジット・SNS画像が実際に選択した素材に合うか。写真、合成の再現画像、創作イラストを取り違えない。

不合格は `assets/generated/manifest.json` の `rejected` に記事指紋・対象JPEGのSHA・具体的な理由を記録する。同じ変更で `content/visual_reviews.json` の旧acceptedをrejectedへ更新するか削除し、後の再取込でも過去の合格が復活しないようにする。既存JPEGの生成記録、seed、記事指紋を付け替えて再承認しない。再生成は既存無料経路のみで、品質保留の再試験は明示slugのレビュー用生成として扱う。新しい画像を実際に見てから採用を判断する。

写真が使えない場合、本文に合う専門SVGを `assets/editorial-scenes/` に用意できる。`reviewed_story_scene` は記事指紋、主題、寸法、アクセシブルな説明、外部依存のないSVGを照合する。記事変更後に古い挿絵を自動流用しない。未検品・不合格のJPEGとその派生動画はHTML・OGP・RSS・配布対象から外し、安全なイラスト／承認済み素材で記事閲覧を続ける。

## 選抜動画の確認

発行・日次編集・サイト日次・週次SEO/UXは既存の枠で `python3 scripts/publish_motion_clips.py --plan` を確認する。状態と次の作業は[MOTION_CLIPS.md](MOTION_CLIPS.md)に従い、未解決分を既存の結果・引き継ぎへ「slug／待ち理由／次の作業と担当」で残す。OFF時の空一覧は未処理なしを意味しない。

`visual_review_required` は現在の実画像を本文と照合し、上の採用条件で記録する。`image_required` は品質保留も含むため `scripts/visual_review.py` で詳細を確認する。`captions_required` は発行・改稿担当へ本文と3字幕の再確認を渡す。サイト担当が字幕の指紋だけを更新したり、未目視の承認を作ったりして解消しない。改稿担当は本文を直した後の字幕も読み直す。

準備完了・生成済み・本番配信済みを分け、待ち理由は読者画面へ出さない。既存の自動生成で進め、タスク・時刻・OFF設定・選抜の目安や生成上限を変えない。

## 表示確認と公開の完了

日次は変更箇所と新着を重点確認。週次は一面、一覧、記事、保存一覧、連載、発行号を確認する。スマホ360/390px・中間768px・PC1280px程度を使い、横はみ出し、見出しの折返し、画像切れ、余白、動画選択、タップとキーボードの操作位置を実画面で見る。エラー・空一覧・保存済み・画像代替など、変更に関係する状態も確認する。

必要なテストと最新headのCIを通し、安全な修正は統合して公開revisionと対象ページ・画像の実配信を確かめる。静的プレビューのAPIエラーを本番障害と混同しない。画面を見られない時は目視確認済みと記録せず、確認可能な範囲と残りを分ける。計測を無効化できる運営者用設定または読み取り検証を使い、確認操作を読者の成果に含めない。

報告は「確認した問題→変更→テスト→本番確認→次へ残す具体的課題」を短く記す。実施内容のない改善宣言、同じ障害の長文反復、内部運用の説明を読者画面に追加しない。
