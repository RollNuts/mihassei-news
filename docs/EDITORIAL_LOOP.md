# 未発生新聞｜継続改善の編集ループ

このメモは発行・日次点検タスク向け。公開サイトの読者画面には載せない。**1本の面白さを先に改善し、新機能を増やさない**（特に2026年11月3日〜9日の7日間）。追加課金、外部AI API、画像API、広告費、新規管理画面は不要。

## 本紙のコンセプト｜未来を当てる新聞ではない（2026-11-03 決定）

**「5年後はこうなってるかも」と、今の世の中を少し大げさにして笑う架空ニュース新聞。** 未来を的中させるつもりはない。冷笑・毒舌・説教を無理に加えず、誰もが知る日常の違和感を、2031年の小さな珍事として真顔で報じる。

- **今日の現実 → 一段大げさな5年後 → おかしな結末**の順で発想する。元ニュースの固有の制度・行動・価値観を使い、単語だけ借りた強引な連想は避ける。
- 予知や投資助言に見せない。記事の冒頭やサイト説明では**創作・架空ニュース**だと一目で分かるようにする。5年後という舞台と出典・公開日時の区別は維持する。
- 「誰が何をしたか」だけでなく「今の何をちょっと茶化しているか」が読者に自然に伝わること。風刺の解説を足すのではなく、登場人物の行動と結果で伝える。
- **未来を真剣に予想する必要はない**。「そんなわけない、でも少しありそう」と笑える飛躍がよい。無理に攻撃的な冷笑にせず、人そのものではなく社会の仕組みや行き過ぎを笑う。
- 連載「未来相場観測室」は現実の資料に基づく市場分析であり、架空ニュースとは明確に区別する。推理小説の創作も維持。新聞名「未発生新聞」とサイトURLは変えない。
- 今後のすべての発行枠と日次編集点検に適用する。**誇張の方向とオチが違うか**を先に比較し、単純な風刺キーワードの追加で済ませない。

## ① 書く前｜直近の弱点を引き継ぐ

- `content/articles.json` の**直近20本**を実際の `published_at` 順で確認し、見出し、元ネタ、冒頭、最後の一文、カテゴリ、笑いの仕組みを比べる。公開日の偽装はしない。
- `python3 scripts/audit_satire.py` の `NEXT SLOT (advisory)` と `::warning` を参考にする。自動チェックは文章の表面の反復を見つけるだけであり、面白さを採点するものではない。
- 前の1〜3枠の見出し・末文と同じ逆転（AIが選別、申請が無限、謝罪、担当者の一言）を避ける。元記事が変わっても同じオチなら発想を変える。
- 本当に公開された**当日の新しい一次情報または信頼できる報道**を探す。公開日時、記事内容、元の文脈を確かめる。検索結果の日付だけを信じない。SNSのトレンド規模や炎上数を捏造しない。

## 最優先｜初見の読者が迷わない文章（2026-11-03改訂）

今回の16本一括改稿と追加5本の再編集で得た方針。**説明を増やすのではなく、読者が最初に見る光景を具体的にする。** 専門知識や元ニュースの記事を読んでいなくても成立すること。

- **見出し＋冒頭2文を声に出して確認**：「誰が」「何をした」「何がおかしい」が初見で分かるか。本文を最後まで読まないと架空ルールを理解できない場合は、設定そのものを減らす。
- **場面から書く**。「2031年、架空の○○社が新制度を導入した」を連発せず、実際に起きた会話や見えた物を先に置く。架空の企業名・未来の年は必要な位置で説明する。例：「お土産は市外へ持ち出せません」という店の貼り紙、「笑わないでください。番組の経営がかかっています」という収録の声。
- **原因→行動→結果を一続きに**：極端な設定を出すなら、そのルールの内容を1文で説明する。突然別のサービス・登場人物・制裁制度を加えてつじつまを合わせない。感想・解説より場面、原因と結果の順に並べる。
- **summary は読者用の2文以内**：見出しと同じ言葉を並べず、「なぜその珍事が起きたのか」を自然な日本語で補う。誰でも知る言葉に直せる造語は避ける。
- **オチは具体的な行動**：「担当者が困惑」「今後検討」「皮肉な結果になった」で説明して終わらない。最後の1文は、その話だからこそ生じた人物の動き・発言・具体物で閉じる。
- **読者導線の文章も整合させる**：記事の見出し・概要を変えたら `content/editorial_picks.json` の紹介文も見直す。記事本文にない結末を紹介文で断定しない。
- **元ニュースとの接続が弱いなら作り直す**：天気の話題を単語だけ借りて職場の話にする、といった無理な連想は避ける。元ネタの具体的な行動・制度・文化から、たった一段の拡張を作る。別のニュースに差し替えても全く同じ話なら題材を選び直す。
- **実在と創作の線引き**：5年後の架空の出来事・架空の発言を実在団体や人の発言に見せない。既存の公開日・出典・フィクション表示・無料運営を保持する。

**掲載直前の読み返し**：見出しだけ→冒頭2文だけ→全文→末文だけの順に読む。理解に必要な背景が末尾に来ていたら先に移す。面白さの数値化はしない。自動警告は助言であり、発行停止には用いない。

## ② 書くとき｜見出し→現場→別のひねり

1. 「今の何が滑稽か」「5年後にどこだけ行き過ぎるか」「一番おかしい具体的な行動は何か」を1行ずつ用意。
2. **仕組みの違う見出しを2案**作る。3秒で異常さが分かる案を採用し、元ネタを知らなくても読めるようにする。
3. 冒頭は会話・行動・場面を優先。架空企業の発表や制度説明は必要な分だけ。短報は2段落180〜350字を目安に、必要なら3〜6段落。段落数で水増ししない。
4. 本文の後半には**見出しに書かなかった2回目の逆転**を置く。末文を「担当者は困惑」「検討している」で逃げず、誰かが実際に何をしたかで閉じる。自然に余韻が残るなら台詞でもよい。
5. 表面的な言い換えではなく、人物の誤解、善意の暴走、皮肉な成功、ファン文化、日常の小さな矛盾、言葉遊びなど笑いの構造を変える。政治・社会の論争も事実と創作を区別し、実在する私人への攻撃はしない。

## ③ 公開するとき｜公開できる物だけ

- 出典URLと`source.published_at`を検証。架空記事にはフィクション表示。 `fiction_at` は元情報の5暦年後。`published_at` は初回公開の実際のJST日時で、改稿時は`modified_at`だけ更新。
- JSONとリンク・本文の整合性を確認し、既存のGitHubテスト、公開サイトのSHAと記事表示を可能な範囲で検証。コミット成功と本番配信成功を混同しない。
- **毎日9枠の発行努力目標は維持**。警告を理由に無投稿にせず、候補を変えて短くても独自の作品を目指す。出典・安全・ツールの実際の制約で発行不能なら正直に報告。
- 新規の有料サービス、AIトークン課金、有料プランへの移行、アクセス水増し、Xへの大量自動投稿はしない。

## ④ 次の発行へ｜小さく学ぶ

- 各枠の終了時に「今回は前回と何を変えたか／次枠は何を変えるか」を**各1行**残す。記事URLと公開済みか未確認かも残す。報告は編集メモであり、閲覧者向けの記事に書かない。
- 日次点検では直近6〜20記事を振り返り、**一つだけ**次枠への編集方針を提案。繰り返し減少を確認できたら次の仮説へ進む。
- `analytics/daily/` の計測値は累積の匿名ブラウザ識別子で、PV、実人数、閲覧時間、面白さの証明ではない。標本が少ない間は数値で「改善成功」を断定しない。日次の増加や元記事ごとの滞在時間を想像しない。
- 2026年11月10日に11月3〜9日の短報、テーマ、オチと**確認できた範囲の**反応を振り返り、次週の編集方針を一つだけ見直す。新機能を増やす判断はその後。

この運用は外部のLLM API・GitHub Actionsの追加トリガー・新規DBを必要としない。警告スクリプトは助言のみで、発行や記事表示を止めない。
