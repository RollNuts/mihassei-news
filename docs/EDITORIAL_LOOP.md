# 未発生新聞｜継続改善の編集ループ

発行・日次・週次編集の正本。**1本を読む価値を先に改善する**。担当・重複防止・公開完了は[OPERATIONS.md](OPERATIONS.md)、画像採用は[VISUAL_OPERATIONS.md](VISUAL_OPERATIONS.md)に従う。内部規則を読者画面へ載せない。

## 発行の目安と候補の選び方

通常は07:30〜19:30のコア7枠で**1日7本を目安**にし、21:30・23:30は公開失敗・遅延の回収か、その日のうちに出す価値が明確な強い企画だけの予備枠にする。既存9枠・1枠1本・JST1日最大9本を維持する。弱い案で7本や9本を埋めず、見送りを後から補充しない。

`trend` 3本／`social_life` 2本／`original_satire` 2本は紙面の偏りを見つける目安。出典の確かさ、初見の分かりやすさ、面白さを優先し、レーン不足の警告を発行ノルマにしない。

**2026-11-10 00:00 JST以降の新作は、JST日ごとの最初の7本以内に政策発表・新製品発表を各1本以上入れ、風刺は予備枠を含め日内最大3本にする。** 形式は下記の`editorial_form`で記録する。候補を追加した各時点で、未達の形式数が残りのコア本数を上回る追加はCIで拒否する。8本目以降の帳尻合わせは認めず、弱い原稿や有料サービスで救済しない。未達なら理由と不足形式を既存の発行引き継ぎへ残し、枠やタスクを増やさない。

**2026-11-10 00:00 JST以降の新規公開は、公開カテゴリの「暮らし」を予備枠を含め1日2本まで、最初の7本を5面以上にする。** カテゴリは`build.CATEGORIES`の既存8面を使う。適用開始前に公開された当日の既刊も本数・面数へ含め、候補追加後に5面へ届く残り枠がなくなる追加はCIで拒否する。開始前の既刊は遡及拒否・再分類せず、カテゴリ名だけの付替えや8本目以降で帳尻を合わせない。内部レーンの`social_life`は公開面の「暮らし」と別軸であり、レーン比率が整っても面の偏りは解消しない。

各枠は候補を作る前に、最新mainで実行当日のJST日付を指定して次を実行する。表示されたカテゴリ実数・残り基本枠・`担当面`と直近7本の見出し・summaryを使い、下記の題材比較を行う。同じ日の別の配分表は作らない。原稿追加後と公開直前には同じ日付で`--check --day YYYY-MM-DD`を実行する。

```sh
python3 scripts/editorial_mix.py --day YYYY-MM-DD
```

作業環境にリポジトリがない場合、このコマンドは同じ最新mainのrevisionから取得した`scripts/editorial_mix.py`と`content/articles.json`を同じディレクトリ構成へ置けば、追加依存なしで実行できる。Pythonを実行できない場合は実行済みとせず、実行不能の理由と確認したmainのrevisionをタスク結果に残す。公開前のスクリプト実行とCIは省略しない。

- 通常は指定された**担当面の実題材で2〜3候補を同じ情報量で一度だけ比較**する。未掲載かつ直近7日で少ない面を優先する出力に従い、カテゴリ名を判断材料にせず、当日既刊と直近7本の見出し・summaryから**何が主題で、誰や何が、どの現場で動き、何が変わるか**を見渡す。候補も一文にし、似た既刊だけ本文を確認する。買い物・試着・窓口・近所の交流など個人の生活体験が続く時は、担当面の別の活動・現場から探す。経済なら生産・供給・競争、技術なら機構・実験・探査、政治なら政策判断・交渉・制度の実施、スポーツなら勝敗・戦術・記録など、その題材の中核が動く出来事を比べる。政策発表・新製品、個人の観察、商売、時事、静かな余韻も扱い、身近な話を禁止せず記事に合う伝え方を選ぶ。
- 単独で公開したい理由が残らなければ、担当面の中で別の入口・人物・出来事へ**一度だけ**切り口を変える。それでも弱ければ見送り、楽な暮らし案へ戻したり、候補3案の作り直しを無限に繰り返したりしない。未達は既存引き継ぎへ残し、弱い7本目や未確認の流行を強制しない。
- 毎枠は直前の記事と、候補に似た既刊を比較する。人物名・商品・カテゴリが違っても、「個人が新サービスを試し、少し便利になる」など主役の役割・行動・結果が同じなら別の切り口を選ぶ。一方、生活場面が一部あっても、産業・競技・制度などの中核に異なる変化が出る記事は扱える。`reader_interest`やタグの分散、単語の有無だけで判定しない。直近20本の横断再読は日次・週次へまとめる。当日既刊・予定枠・未統合PRの重複確認はOPERATIONSに従う。
- `editorial_mix.py` のレーン・関心・トーン・着地・キャラの出力は偏りを見る助言。公開カテゴリと形式は上の必須条件で確認し、それ以外を毎枠すべて回転させる手順にしない。原稿完成後に本文に合う分類を記録し、自動警告・CIを面白さの合格判定に使わない。

### 週末の軽い未来企画（既存枠）

- **毎週土曜13:30 JSTの既存発行枠**は、週1回程度の軽い未来エンタメ・ファッション案を優先して比較する。日次編集が[既存候補欄](EDITORIAL_IDEAS.md)へ準備し、通常の2〜3案を一度だけ比べる手順で採否を決める。毎回の必須公開や年齢・性別の本数ノルマにせず、弱い案や鮮度・内容を確認できる出典がない案は採らず、通常の良い記事へ戻す。枠・タスクは追加しない。
- 通常は`desk_next`の担当面を優先するが、この枠だけは表示された候補面からエンタメ・暮らし・技術等を実主題で選べる。当日全体で配分を調整し、暮らしの上限・最初の7本の面数・形式条件は維持する。カテゴリ名だけを付け替えない。
- 主役は**架空の20歳以上の成人**とし、本文と`scene_prompt`でも年齢・成人設定を明確にする。架空のアイドル、新しい水着、屋内プール・海辺イベント、衣装などの具体的な新しさと本人の動作を記事の主題にする。ビキニや、衣装が動く瞬間・振り向く自然な構図による非露骨な「少しドキッとする」雰囲気も扱える。露出だけで穴埋めせず、サムネイルと本文の人物・衣装・場面を一致させる。実在人物・ブランドを使わず、既存の出典確認・実写QA・追加費用0円を守る。

### 取得元

- **検索トレンド**：Google Trends「急上昇中」日本（`https://trends.google.com/trending?geo=JP`）。リポジトリには無料・APIキー不要の `python3 scripts/trend_brief.py` を置く。検索語・概算検索量に加え、RSS内に埋め込まれた関連ニュース見出し・媒体・HTTPS URLを最大3件の**検証候補**として返す。関連ニュースは事実確認済み扱いにせず、実ページを開いて日時・内容を確認してから `source` / `real_detail` に使う。RSS取得不能・空フィード・壊れたXMLは成功扱いせず、ブラウザで同ページを確認する。有料APIへ切り替えない。
- **Xトレンド**：ログイン済みのX公式「話題を検索」が取得できる場合は `x_official`。取得できなければ、ブラウザ検索で確認できる公開集計を `x_public_aggregator` として補助利用してよいが、**「X公式ランキング」「X公式トレンド」とは書かない**。公開集計だけを事実の根拠にはしない。
- トレンドは**題材発見のシグナル**。記事の現実部分は、一次資料または独立した信頼できる報道で別途検証する。Google Trendsの検索増加自体を、その話題の内容が真実である根拠にしない。検索トレンドもX側も実際に確認できない枠では `trend_observation` を推測で作らず、担当面のまま品質の通る `social_life` / `original_satire` へ切り替えるか、その枠を見送る。

### 発行前の記録

2026-11-05 20:00 JST以降に新規公開する記事は内部JSONへ次を持たせる。

- `editorial_lane`: `trend` / `social_life` / `original_satire`
- 上記の形式条件を適用する新作は`editorial_form`を一つ持つ。`satire`（矛盾・逆効果・皮肉を主題にする風刺）／`policy_announcement`（政策の対象・仕組み・条件・導入後の変化を伝える発表）／`product_launch`（新製品・サービスの機能・制約・使用場面を伝える発表）／`feature`（暮らし・文化などを描く企画）。レーン・トーン・着地とは別に本文の主目的で決め、「発表」と名付けただけで失敗や皮肉が中心の原稿は風刺として数える。開始前の既刊に後付けせず、公開前の6点で本文と照合する。
- `editorial_signature`: `target`（主題は何か）／`action`（誰が何をするか、何を導入するか）／`outcome`（目に見える具体的な結果）。**2026-11-06 22:00 JST以降は `present`（今すでにある兆候・行動・需要・不満）も必須**。「公開前の6点」に沿って、今の何から5年後の出来事を描いたのかを公開前に固定する。
- `editorial_tone`: `plausible_future` / `comic_exaggeration` / `observational` / `wildcard`
- 2026-11-06 09:00 JST以降は `editorial_payoff`: `dialogue`（最後の一言） / `action`（人物の行動） / `visible_result`（残った物・画面・光景） / `ironic_success`（目的は達成したのにおかしい） / `quiet_aftertaste`（大オチを置かない余韻） / `wordplay`（言葉そのもののズレ）
- 2026-11-06 20:42 JST以降は、X自動紹介候補の記事で自然に作れる場合だけ`x_share_lead`を1本持たせる。これはsummaryの再掲ではなく、読者が「自分にもありそう」「それ、やってない？」と記事へ入れる短い導入。問いかけ・自分事化・違和感・場面提示のどれかを毎回固定せず、記事ごとに一番自然な形を選ぶ。変になる場合は省略してよく、投稿側が従来文へフォールバックする。詳細な禁止事項と文字数処理は`social-bot/article-picks/README.md`を正本とする。

- `plausible_future` の場合のみ `plausibility_basis`: `present_signal`（今すでにある兆候）／`continuation_force`（なぜ5年続くか）／`future_result`（5年後に目に見える結果）
- `trend` の場合のみ `trend_observation`: `source_kind`、`term`、`observed_at`、`url`、`verification_urls`

`trend_observation.observed_at` は**Google Trendsなら12時間以内、X系なら6時間以内**。古い観測語を「今日の流行」として持ち越さない。検証URLには記事の `source.url` を必ず含める。X公開集計を使った場合も、実際の出来事は別URLで検証する。これらは内部編集メタデータであり、読者向け本文に「トレンドだから選んだ」と説明しない。**トレンド語とX発見語は別物として扱う。** `trend_observation.term` を自動でハッシュタグに昇格させず、`x_discovery_term` は記事の角度を完成させた後で選び、同じ語を `x_tags` または主題銘柄の `x_tickers` に明示する。

### トレンド接続の確認

上の既存メタデータには、①何が起きて今話題なのか、②元ネタを知らなくても分かる行動・需要、③従来と導入後の差または目的と結果の食い違い、④完成原稿を探す人の語、⑤現実側の固有の事実、⑥その事実だから生まれる未来の出来事を記録する。単なるランキング入りや「話題だからAI化・義務化」では採用しない。

- `real_detail` は数字・候補数・発表内容・制度変更など、その日の事実を一つ。`source.topic`で検証でき、見出し・summary・冒頭1段落のどこかに出す。summaryと冒頭に同じ前置きを重ねる必要はない。
- `unique_hook` は、別の株価下落・商品・ランキングへ名詞を替えても同じ話にならない接続にする。一方、固有名詞の予備知識がないと理解できない案も落とす。
- `x_discovery_term` は原稿完成後に選び、実際に送る追加発見語の先頭へ置く。実在名の扱いは下記「ホットニュースをフックにする」に従う。その条件を満たし、観測語が自然なハッシュタグになり記事の中心でもあるなら優先し、その語を見出しかsummaryにも置く。代替語は見出し・summary・`source.topic`に明示される語を使う。
- 2個目のX発見語も同じ公開名の条件を守り、見出し・summary・`source.topic`・冒頭1段落のどこかにその語が必要。`x_tags`へ明示し、無関係な人気タグで弱い記事を救済しない。取得元の正確さとX投稿の詳細は各正本を参照する。

### 分類と紙面の幅（日次・週次で見る）

冒頭の公開カテゴリ・形式条件の中で風刺・政策や製品の発表・暮らし文化を混ぜ、恋愛・婚活や飲食・玩具・遊びの新しい流行も時々扱う。これらも現在の兆しから5年後に起こりそうな出会い方・商品・楽しみ方の変化として具体的に描く。以下の関心・トーン・着地は公開カテゴリと別軸の助言に留め、追加の割当表を作らない。性別で題材や読者を決めつけず、弱い記事で比率を埋めない。

人物は題材に合う世代・立場から選び、学生、働く世代、シニア、家族などを自然に描く。人物を置く必然性がなければ、車・装置・競技場・建設現場など、物や出来事自体を主役にしてよい。直近と同じ年齢層・役割・室内の構図へ寄せず、年齢や性別の割当は作らない。20歳以上の条件は[週末の軽い未来企画](#週末の軽い未来企画既存枠)の水着・アイドル企画に適用し、一般記事の人物へ一律に広げない。

2026-11-07以降の新作は内部JSONの `reader_interest` を一つ持つ。

- `work_money_tech`：仕事、投資、お金、AI、端末、業務効率
- `beauty_wellness`：美容、服、セルフケア、健康習慣
- `relationships_social`：恋愛、友人関係、マッチング、SNS
- `food_travel_shopping`：食、旅行、買い物、店、消費行動
- `fandom_entertainment`：推し活、ライブ、ゲーム、映像
- `family_home`：家族、家事、住まい、子育て
- `general_society`：上記に寄せると不自然な社会・制度

関心やトーンは実際の題材を広げる補助で、最低本数や毎日の回転表にしない。生活への関心がある記事でも、製品・競技・政策など何が主題かで公開面を決める。

`editorial_tone` は、今の流れが続く結果を描く`plausible_future`、一つの前提を大胆に誇張する`comic_exaggeration`、身近な空気を観察する`observational`、SF・突飛な発明やサービス・シュール・言葉遊びなどの`wildcard`。`editorial_payoff` は最後の一言`dialogue`、人物の行動`action`、残る光景`visible_result`、皮肉な成功`ironic_success`、静かな余韻`quiet_aftertaste`、言葉のずれ`wordplay`。政策・製品にも`plausible_future / wildcard`や`action / visible_result / quiet_aftertaste`を使え、トーンだけで形式を決めない。同じ分類だから落とさず、実際の展開が続いていないかを見る。

`recurring_character` は任意で `mina / nono / yuu` のいずれか。ミナは失敗回避の比較、ノノは好きなことの効率化、ユウは数字による最適化に巻き込まれる普通の人として使える。目安は1日0〜1本、同じキャラは7日で2本まで。初見でも単体で分かることを優先し、キャラのための弱い記事や同じ口癖・失敗を作らない。停止中の旧Xキャラ投稿レーンは復活させない。

### 未来日付と5年後の出来事

`fiction_at`の年は実際の初回掲載日時`published_at`から5年進め、月日・時刻・タイムゾーンを保つ。**これは物語の中で全員に5年間我慢させる指示ではない。** 年代は日付欄に任せ、本文は出来事から始める。

`plausible_future`では、現在確認できる兆候→5年続く具体的な力→2031年の結果を`plausibility_basis`へ記録する。「AIが進化する」「社会が変わる」だけでつながず、年号を現在へ戻すと意味が変わる出来事を選ぶ。他のトーンで強い観察や可笑しさがある記事を、無理に未来化しない。

政策・製品の発表を現実的な延長だけに限定しない。`wildcard`では突拍子もない未来車や新しい発明・サービス、SFの制度も扱い、作中の仕組み・利用場面・世界や暮らしへの変化を新聞調で読ませる。失敗や皮肉のオチは不要。2031年の創作設定と、出典で確認した実在の発表・科学的性能の事実を分ける。創作の発明を、実在機関やメーカーの実際の発表・実証として書かない。

今のニュース・期待を2031年から振り返る回顧構成も使える。2026年側の日付・発表・数字・予測は実在の出典で確認し、編集側の推測を「当時の予測」として創作しない。主役は2031年の出来事とし、「予測が外れた」という答え合わせや過去説明だけで終わらせない。期待が実現・定着・修正された後の暮らしや利用方法の変化まで描く。

## 原稿を選び、書く

### 毎回の発行で使う短い執筆プロンプト（最優先）

> 各枠はeditorial_mix.pyで担当面・不足条件・直近7本を確認。カテゴリ名に頼らず主題・主役・現場・行動・結果を比べ、同じ生活体験へ戻らない2〜3案を担当面で一度だけ比較する。変わる能力・規模・活動を具体物と動作で描き、人物は必要な時に置く。手順は時系列、初出の用語は平易に。好奇心・遊び・達成も動機にする。画像生成前に「公開前の6点」で意味と本文の発見を確認。弱ければ一度だけ改め、なお弱ければ見送る。実写の場面を考え、完成後に必須メタデータ・出典・日時・重複・公開を正本で確認。

### 公開前の6点（発行・日次・週次で共通）

**毎記事、画像生成より前に**出典や内部メタデータを隠し、見出し→summary→冒頭2文→全文→末文の順に読む。面白さの評価より先に、公開文だけを根拠に「誰が何をし、何がどう変わった話か」を一文で言い直す。その要約が作れても、本文の主語・指示語・因果・時間順を読者が補わなければ動作を追えない原稿は通さない。理解に迷う原文を特定して書き直し、同じ順に再読する。一度直しても意味が通らなければ、その枠は見送り、画像生成・公開へ進めない。見出し・summaryと本文の一致、数の比較対象と単位も確認する。`reader_clarity`等の自己申告、執筆時の意図、CI成功をこのレビューの代用にせず、以下の既存6点で判定する。

1. **見出しに読む理由がある。** 誰が何をし、何が新しい・従来と違う・可笑しいのかを初見で言える。前記事・流行語の知識や「まさか」「話題に」などの煽りで出来事を隠さない。
2. **冒頭で場面と変化が分かる。** 最初の2文に具体的な人・物・動作を置き、何が原因でどう変わったかを示す。政策・製品は、人・装置・組織や現場のどれが主役かを決め、仕組みが動く一場面から見せる。購入・申請・感想を述べる個人を毎回置く必要はない。「手続きが便利になる」のような抽象語だけで済ませず、制度名や専門語は初出で普段の言葉に言い換える。「予約便」なら「予約した客を迎える車」のように実体を示し、何をどこへ運ぶかを読者に補わせない。現実の背景は必要な短い一文にし、主役より長く説明しない。 写真を見なくても主要な物の形や置き場所を思い浮かべられるよう、働きを使う前に実体を示す。実物と画面内の物が混在する話では、その区別を先に置く。専門語や複数の固有名を一度に出し、読み手に舞台の組み立てを任せない。
3. **人や組織がその方式・行動を選ぶ理由が見える。** 導入理由と現行の手段との比較は、作中の選択・動作・条件や短い一文で示す。`behavior_basis.evidence_quote`はその公開文から抜く。「普通なら別の方法でよいが」と想定反論に答える段落を毎回置く型にせず、理由が伝わった後は出来事を進める。「未来だから」で理由を省かず、説明のために不要な損や圧力を作らない。
4. **企画に単独の価値がある。** 人に話したくなる場面や発見があり、未来の記事では現在から変わる能力・規模・活動・制度が本文の出来事に表れている。年号だけを現在に戻して同じ話になるなら、企画の変化を再検討する。政策は対象・仕組み・導入後の変化と条件、製品はできること・制約・使用場面が読みどころになる。身近な矛盾や恋愛・遊びも扱い、全てをSF発明にせず、制度や評価指標を登場させること自体は加点しない。
5. **本文の出来事を追え、読む分の発見がある。** 誰がいつ何をし、その結果どうなったかを公開文の言葉で追える。複数の人物や物が登場した後の「本人」「それ」「球」などは、どれを指すか確かめる。途中で本文にない主語・対象・原因・時点を補わなければ成立しない箇所や、見出し・summaryで断定した出来事が本文にない箇所は書き直す。そのうえで、見出しの反復だけでなく、人物の動き・仕組み・使い方・具体的な結果から理解や余韻が増えるかを見る。一文要約ができても、物が誰の手から誰へ渡り、どこへ移るかを読者が補完しなければ読めない原稿は通さない。売買と運搬など複数の主体が関わる説明は、主体と段階を分ける。作業開始後に安全説明や必要な準備へ巻き戻さず、過去の原因を説明する場合は「前夜」など時点の切替を明示する。summaryの人数や結果を本文で描いた範囲より広げない。同じ前提から因果をつなぎ、別制度や二度目の逆転、最後の教訓で補わない。大オチや冷笑は必須ではない。
6. **直近と話の中身が重なっていない。** 主題・主役の役割・行動・結果・舞台を比べる。人物名や商品だけを替えた利用体験、同じ報告指標・追加手続き・担当者の理屈へ戻る案は別の切り口を選ぶ。違いは公開文と既存`editorial_signature`の両方で説明できること。舞台を広げるだけの抽象的な大ニュースにもせず、何が起きるかを具体物と動作で見せる。「3案中で一番まし」だけの相対評価を採用理由にせず、弱いままなら上の一度の変更で打ち切る。

レビューでは、公開文から読めた出来事の一文要約を作る。理解に迷った箇所は「原文／何が特定できないか／修正後」を既存のタスク結果へ短く残し、直した箇所を再読した結果も示す。採否の根拠は、従来どおり「導入・行動の理由が見える箇所／新しさ・具体的な結果・余韻が残る箇所」の短い引用2箇所と、反証への判断1文でよい。新しい自己採点欄・合格メタデータ・確認記録専用ファイルは作らない。読む価値を本文外の解説で補点せず、本文にない動機・損・社会批判を推測して補わない。

### 本文の組み立て

- 候補の見出しは、事実を真顔で言う形と、矛盾や具体的な結果を見せる形を比べる。さらに別の見出し3案や候補トーナメントを必須にしない。
- summaryは1〜2文で見出しを補う。本文は自然な2〜6段落とし、字数・段落数の穴埋めをしない。見出しと冒頭で「誰が・何をするか」を具体的に示し、曖昧な略称、説明の詰め込み、内部の企画理由の羅列を避ける。主語や原因を省略して短くせず、同じ説明の繰り返しを削る。
- 移動・予約・利用などの手順を扱うときは、誰がいつ何をするかを起きた順に書く。後段で主役の動作を巻き戻して設定を追加せず、2026年の背景説明を毎回独立した長段落にしない。根拠は元資料で確認し、必要な比較と作中の行動理由は短く残す。
- 中心となる前提は一つ。政策の導入や製品の機能も、同じ前提から人物の選択と結果を進める。誇張を選ぶ場合は大胆でよい。見出し・summaryで断定した出来事が本文でも起きているか照合する。
- 例えば個人アプリの色の意味が部署ごとに違う場面や、誕生日の主役が自分の名でケーキを予約する場面は、説明以上の発見を作る。コートを売るための保管料が膨らむ話を、別の品物でもう一度繰り返すだけでは弱い。

### 必要な記事には小さな解説図を添える

位置関係・物の内部・動く順番・実物と映像の違いを頭の中で組み立てる負担が大きい記事や、一つの変な仕組みを図にすると直感的に伝わる記事には、補助の解説図を1枚まで添える。読み手が集中して設定を覚えなくても、何が起きる話かをつかめることが目的。短い行動だけで伝わる記事には付けず、全記事への一律追加や本数ノルマにしない。

- 図で分かることは一つ。物の絵、短いラベル、必要な矢印で、位置・構造・変化のどれかを見せる。文章を箱に詰めた長いフローや、細かい凡例を読ませる図は避ける。
- 「なんちゃって技術解説」「とんでも理論図」も採用できる。記事の変な仕組みを真顔の断面図・模式図・計器風の表示などで見せ、図自体にも可笑しさを持たせる。新作の中心を大胆な架空の原理にしてもよいが、図を作るために別の原理・専門語・人物名を増やさない。既刊の図は本文にある物・動作・数・条件に合わせる。
- 例えば浮き倉庫なら「倉庫と鋼材は600m移動、案内板は前の場所のまま」、AR球技なら「会場は無風、映像の球は盾の外側へ曲がる」を一目で見せる。写真は現場、図は関係を伝える。
- スマホ幅で拡大せず読める短いラベルにし、図を見てから本文を読んでも別の状況を想像しないか照合する。本文の分かりにくさを放置して図だけで救済せず、写真が必要な記事の実写対応を図だけで完了にしない。

発行・公開後レビュー・日次編集で今回扱った記事は、既存の結果に`図：不要／採用／保留＋理由1文`を残す。図がないことだけで不要と判定せず、何を一目で見せると読む負担が減るかを考え、単純な話なら不要と決める。採用は実際の掲載状態も示し、保留は制作・目視・配信のどこが残るかと次の担当を既存の引き継ぎへ渡す。変更のない記事の図判断を毎回やり直さず、新しい台帳や採点欄は作らない。

採用した記事では、本文1段落目の後に図を表示する。制作・確認・改稿時の扱いは[VISUAL_OPERATIONSの本文内の補助解説図](VISUAL_OPERATIONS.md#本文内の補助解説図)に従い、具体的な目視結果は既存のPR・タスク結果に短く残す。

### 企画段階で画像の場面も考える

記事に合う人物・具体物・現場のどれを主役にするかを選び、一つの動きが普通の光で写る場面を候補の段階で考える。試す・遊ぶ・競う・始める本人の能動的な動きも比較し、準備・受付・待機だけを写真の定番にしない。大人数の細かな関係や読める文字がなければ成立しない時は、その制約を把握しておく。ただし写真にしやすいという理由で弱い題材を採らず、良い記事を画像待ちで止めない。

- `scene_prompt`は最初の短い一文で主役と動作を大きく見せ、次に場所・必要な周辺人物。遠景の群衆や雰囲気だけの会議室を避け、文章の後半がCLIPに読み落とされる可能性を考慮する。
- 写真向けの場面指示に`cinematic / anime / 3D render / glossy / dramatic lighting / poster`など画風を派手にする語を足さない。写真の共通スタイルは生成側で報道スナップに固定する。寸法やSHAだけでは題材・ユーモア・実写感を保証しない。
- 実写風を既定にし、単一の人物・物体・行為で場面が伝わるなら`visual_strategy: "cpu-photo"`。紙面の写真比率は日次・週次の改善材料とし、写真の本数ノルマで題材を曲げない。
- 2026-11-06 22:00 JST以降の新作で、読める文字/UI、厳密な人数や不在、複雑な人物関係、比較レイアウト、実在キャラクター再現を避ける安全制約が不可欠なら、`visual_strategy: "illustration"`と`illustration_reason`を記録する。理由は`readable_text_or_ui / precise_count_or_absence / complex_relationship / comparison_layout / brand_character_safety`のいずれか。写真を要求するscene_promptのままイラストへ逃がさず、生成失敗を隠す分類にしない。
- 実画像の採否・専用SVG・画像待ちの回収はVISUAL_OPERATIONSへ集約する。記事を改稿したら画像と紹介文の整合も確認し、旧JPEGの指紋・seedを付け替えない。

### ホットニュースをフックにする

- 候補を探す時は、直近12時間の主要ニュースを3件程度だけ横断する。大きな出来事は題材の入口になるが、毎枠の最低1案やレーン不足の穴埋めを義務にしない。**具体的な未来の出来事や変化を描ける案を、生活・風潮の案と同じ一度の比較に残す。**
- 元ニュースの要約だけで終えず、「誰や何が動き、能力・活動・産業・制度や生活にどんな変化が起きるか」を5年後の出来事にする。政策発表や新製品の説明も選べる。元ニュースの固有名詞を別の話題へ置き換えても同じ記事になるなら、フックが弱いので不採用。
- **見出し・summary・創作本文・公開用タグや共有文・架空の組織名・画像指示には、実在企業・ブランド・サービス・商品・番組・キャラクターの名前を使わず、それらしい架空固有名を付ける。** 架空の企業・サービス・商品・番組は名称や機能・設定を創作してよい。山・城などの実在地名や日経平均などの市場指標は使える。実在の人・組織・店舗や場所の関係者へ架空の発言・行為・不祥事などを帰属させない。現実の過去実績・観測を架空名へ付け替えず、出典のpublisher・topic・URLには事実確認に必要な元資料の正式名を残す。
- **見出しには、記事の核である場合だけ現在の話題語を自然に残す。** 例：米中間選挙、利上げ、スマートフォン、新制度など。SEO目的で無関係な固有名詞やトレンド語を足さない。元ニュースを知らない読者でも見出しだけで出来事の新しさや違いが分かることを優先する。
- ホット候補は原則12〜24時間以内の事実を使う。結果が未確定の選挙・相場・災害等は未確定と明記し、予測を確定結果として書かない。48時間を超えた話題は、継続中の新しい展開がある場合だけホット枠として扱う。
- 選挙・政治は特定政党への支持・反対を呼びかけず、制度の仕組みや変化を描く。風刺を選ぶ場合は報道、企業、人間の先回りや建前と行動のずれを扱う。実在候補者の発言・行為を創作しない。
- **災害・戦争・武力衝突・テロ・大量死傷事故は、ホットニュースだからという理由では採用しない。** 災害は救助・避難・警報が続く急性期と原則72時間以内は風刺記事の直接フックから外す。戦争・武力衝突は戦闘や死傷が続く局面を直接の笑いにしない。死者・負傷者・避難者・被災者・人質・現場要員の苦痛、被害規模、攻撃そのものをオチにしない。
- 例外的に後日扱う場合も、公式情報で状況が確認でき、題材を「復旧制度、行政手続き、企業対応、情報流通、便乗商法、周辺の過剰反応」など被害そのものから離れた構造へ移せる時だけ。実在の被害者や交戦当事者に架空の台詞・行為を与えず、見出しで惨事をクリック誘導に使わない。迷う場合はその枠では採用せず通常題材へ進む。
- 発行後は「ホットニュース由来だったか」を内部メモにだけ残し、PVやX反応と後から比較できるようにする。少数例からホット題材が必ず伸びると断定しない。

### 続報を出すとき

- 一度扱ったホットニュースでも、**現実側に新しい事実・結果・反応が出たら続報候補に戻す**。選挙結果の確定、追加発表、決算後の反応、製品発売後の現象など、前回の記事公開後に確認できる新展開が必要。同じ元記事・同じ事実を言い換えただけの続報は作らない。
- 続報は既刊を改稿せず**新しい記事として発行**し、`followup_of` に直前の関連する記事slugを入れる。公開画面では新記事に「続報」と前記事リンク、前記事には「この話題の続報」を自動表示する。
- **1つの話題は初報＋続報2本の計3本で終了する。** 4本目の `followup_of` はビルドでも拒否する。3本出した後に大きな新局面が来ても、続報チェーンを延命せず、単独で記事にする価値がある時だけ新規題材として再評価する。上限回避のためにリンクを外して実質4本目を出さない。
- 前回の架空設定をそのまま膨らませるだけでは不十分。`新しい現実の事実 → 前回とは違う人物の行動または一段進んだ結果 → 新しい発見` を作る。見出し・末文・展開の仕組みが前記事と同じなら続報ではなく重複として落とす。
- 続報だから前記事を読まないと意味が分からない構成にしない。見出しと冒頭2文だけで今回の出来事を理解でき、前記事リンクは追加文脈として機能させる。関連する話題タグは必要に応じて再利用するが、前記事の分類を機械的にコピーしない。
- PVが高い記事を理由に続報を捏造しない。続報候補の採否は新しい公開事実と記事としての面白さで決め、PV・X反応は公開後の比較材料にだけ使う。
- 日次・週次では、実測PV・X反応・コメントが相対的に強かった記事を**続報ウォッチ**へ戻してよい。ただし反応は「もう一度調べる価値がある」というシグナルに限る。前回公開後の現実側に新しい事実がなければ続報にせず、同じ矛盾を別の人物・場面で扱う独立案として再企画する。

### ニュース・風潮・本人案の探し方

- ニュース、2ch/5ch系・Reddit等の公開議論、生活・文化の習慣、本人が出した案を同じ候補テーブルで比較する。新しい制度・製品・生活の変化、日々の不便、見栄、善意の空回り、職場・家族・趣味での矛盾を拾う。当日のニュースがなくても題材は成立する。
- ニュースは直近24〜48時間を優先し、一次情報で出来事と公開日を確認。風潮は直近7〜30日の議論を目安にし、継続する生活習慣も扱う。古い投稿を今日の流行として再利用せず、現在にも当てはまるか確認する。特定の掲示板・ドメイン固定にせず、利用可能な公開ページを選ぶ。
- 掲示板は本文と会話の文脈を読み、URL・実投稿日時・確認日・観察した関心・行動・矛盾を記録する。検索抜粋やまとめサイトだけで一次投稿を読んだことにしない。取得できなければ一度別経路を確認し、別の公開資料や候補へ進む。有料API、ログイン回避、大量収集は不要。
- 一投稿はその人の見方を観察した材料。複数の独立した議論や反対意見も探すが、一部の声を「世間の総意」「世界的流行」に格上げしない。投稿内容の真偽と、そのような不満が語られたことを分ける。
- 記事に移すのは観察した行動・需要や矛盾の構造。元投稿の固有の台詞・洒落・体験談・筋を翻訳したり、登場人物を改名したりして済ませない。架空の人物・場面・行動・結末を自分で作り、私人の特定情報を持ち込まない。
- `source.kind` は元資料に応じて「ニュース」「公開投稿」「生活・文化」を使う。「公開投稿」「生活・文化」はニュース用12時間の鮮度警告の対象外。これは出典・日時・現在性の確認を省く意味ではない。`source.published_at` は元資料の確認済み日時。`fiction_at` は実際の初回掲載日時 `published_at` の年だけを5年進め、月日・時刻・タイムゾーンはそのまま保つ。取得日で投稿日を埋めず、日時が不明なら候補として保留して別の確認可能な資料を選ぶ。
- 本人案は `docs/EDITORIAL_IDEAS.md` に残す。本人提供の創作を実在ニュースや投稿に偽装せず、公開時の出典は着想に関係する実在資料を確認する。無関係なニュースを後付けするくらいなら題材を再検討する。AI・罰則・義務化だけに展開を頼らない。

## 本紙のコンセプトと読者への表示

**5年後の新聞として、試したくなる発明、熱中する競技、恋や遊び、新しい流行、社会の変化を真顔で報じる。** 読者が「見たい・試したい・人に見せたい」と思う具体的な出来事を起点にし、驚き・楽しさ・挑戦・達成も単独の記事価値として扱う。未来の的中は保証せず、実在の発表と創作を分ける。政策や製品は人・装置・組織が実際に動く現場で変化を見せ、風刺では人物の欲や観察の細かさから笑いを作る。明るい話、鋭い風刺、静かな話を混ぜ、毎回、負担や我慢が増える結末へ戻さない。

- **風刺の切れ味は観察の細かさから作る。** 人物は大まじめ、記者は淡々とし、見栄・熱中・善意の空回り・思わぬ成功・言葉のずれを具体的な行動で見せる。本人が楽しむことにも目を向け、罵倒やただ不幸な話で済ませず、最後の行動・一言・結果に笑いを残す。同じ成功宣言・担当者コメントを連発しない。
- 編集上の狙いを実際の読者の声や推薦文として掲げない。初見で分かる出来事・読後に残る発見を公開文で確かめ、確認できた反応と狙いを分ける。

- 創作の注記は共通の紙面に置き、見出し・summary・本文に「架空」「創作」の前置きを毎回足さない。出典は読後に確認できるようにし、現実の報道を創作の裏付けと誤認させない。編集上の狙い・自己採点・改善宣言は読者画面へ載せない。
- 「ありそう／それはない」は読者が未来の出来事を想像する「もしもの二択」。予言の的中率や面白さの採点として扱わない。
- 現実の資料を使う市場分析と、創作ニュース・推理小説を区別する。新聞名「未発生新聞」、URL、5年後の舞台、出典・公開日時の区別は維持する。

## SNSでは見出しとリンクで紹介する

- 記事をXで紹介する際は、`social-bot/article-picks/README.md`の`x_share_lead`方針を優先し、**要約の再掲より、記事へ入る自然な一言**を使う。問いかけや「自分事化」は有効な選択肢だが毎回の型にはしない。自動投稿、記事・発行号の共有、手動用下書きに「創作」「架空」「フィクション」等の定型注記を毎回付けない。内容上必要な語は削らず、実際の出来事や本人の体験と偽る表現はしない。媒体の性格はサイトの編集方針と記事ページで伝える。
- 見出しに独自の笑いがあるなら本文から解説を長く引用せず、短い要約とリンクで記事へ誘導する。架空の閲覧数や「バズった」などの根拠のない実績を書かない。
- **新聞の発行・日次編集担当によるSNS支援は下書きまで**。承認済みの別のX自動投稿タスクは継続し、この記事編集を理由に止めない。その投稿・予約・設定には触れず、有料APIや追加課金を使わない。記事のURL・実際の初回掲載日・出典は変更しない。

## 記事の記録と公開

- 原稿の採用後に、上の既存必須メタデータを記録する。`reader_clarity`が立派でも公開文から同じ状況を再現できなければ、文章を失敗として扱う。メタデータのために物語を増築しない。
- `scripts/editorial_mix.py --check`は、7日以内の同一トレンド語と同一`editorial_signature`の再利用をCIで止める。続報だけは`followup_of`の既存条件に従う。機械警告がないことを企画の合格にしない。
- `tags` / `satire_tags` とX向け発見語は別物。サイトの`tags`は既存語を優先する1〜3個の題材タグ、`satire_tags`は0〜2個の行動・空気への軽い風刺タグ。カテゴリー名や同義語を増やさず、本文にない流行語をSEO目的で足さない。X用の`x_tags` / `x_tickers`は記事に合う語を別に選ぶ。
- 出典URLと`source.published_at`を検証し、実際の初回掲載日時`published_at`と演出の未来日`fiction_at`を区別する。改稿ではURL・両日時・元の出典を保持し、`modified_at`だけ実際の更新日時へ変える。
- 公開のテスト・PR・履歴保護・最新mainとの競合・本番revisionと個別URL確認は、[共通の公開手順](OPERATIONS.md#着手と公開)で行う。見送り時に確認記録だけのmain更新を増やさない。

## 事件面と映像の選び方

- 事件性のある強い場面が見つかれば、通常候補として比較する。盗難・落とし物・ご近所の騒動・取り違えなど、誰がどこで何をしたのか分かる「現場」を先に描き、最後に現場で起きる可笑しな行動・結果を置く。見出しだけで警察・被害者・通報などの事件性を捏造しない。
- 実在事件から着想する場合は実在の被害者・容疑者を茶化さず、**架空の場所・人物・出来事**へ切り分ける。重大な被害や悲劇を安易なギャグに変えない。元報道は創作の裏付けではなく着想元として明示する。
- **全記事を動画にはしないが、放送室を止めない**。発行担当は毎回の新作で動画適性を判定する。JST当日の新規動画選抜がまだ0本なら、映像で具体的な場面と笑いを伝えられる最初の合格記事を原則 `broadcast_feature: true` にする。目安は**1日1本、映像向きの強い記事が複数ある日は最大2本**。無理に枠を埋めず、画像・字幕・安全条件を満たさない記事は静止画のままにする。放送室の最新動画が24時間以上更新されておらず、当日公開記事に適格候補がある場合は、古い3枠を維持するより鮮度回復を優先する。承認済み画像のない記事は動画を作らない。動画が壊れれば画像表示へ戻し、既存画像のハッシュや承認情報を書き換えない。
- 各発行枠では、当日の `broadcast_feature` 選抜数と `assets/clips/manifest.json` の生成状況を確認する。すでに当日1本が選抜済みなら2本目は「静止画より動画の方が明確に面白い」場合だけ、2本選抜済みなら追加しない。未生成の適格候補が残っている時は、鮮度のためだけに候補を積み増さない。
- 選抜時は `content/broadcasts.json` に、本文に実際にある「状況→行動→オチ」の3字幕も**同じ変更内で**用意する。文字数・時刻・指紋の条件は[MOTION_CLIPS.md](MOTION_CLIPS.md)に従う。改稿担当は本文と字幕を読み直して必要な文を直し、指紋だけの付け替えで古い字幕を有効化しない。
- 選抜記事を今回変更した発行・改稿担当は `python3 scripts/publish_motion_clips.py --plan` で今回分の状態を確認し、残る未検品はサイト担当へ渡す。未検品・品質保留は実画像を見て判断し、未解決分は既存の引き継ぎ2行または作業結果に「slug／待ち理由／次の作業と担当」を短く残す。動画待ちで記事を止めず、OFFの解除や選抜の一括追加で解消しない。
- 放送室は事実の速報ではなく**架空ニュースの番組風演出**。無音・少数・小容量、手動再生可能、モバイルの低電力モードと動きを減らす設定を尊重する。追加費用0円、強制再生なしを守る。

## 次の発行へ学ぶ

- **発行担当**は今回の記事だけを完成させ、直前と似た既刊を必要な範囲で見る。日次メモや全体の配分・自動化を毎枠変更しない。一面の実際の新着順を保ち、古い良作の固定や公開日時の変更で弱い新着を隠さない。
- **日次編集**は、前日JSTに公開された全記事を、見出し・summaryだけで終えず、本文と末文まで必ず一度読み返す。まず`clarity_digest.py --day YYYY-MM-DD`、次に同日の`--full-text`を使い、出典・内部メタデータは後から照合する。各記事の「何が起きたか」を公開文だけから一文で言い直し、理解に迷う箇所があれば原文と不足する主語・つながりを特定する。直近20本とは見出し・元ネタ・冒頭・末文・展開の仕組みを比較し、`editorial_form`が本文の主目的に合っているかも確かめる。面白さの磨き込みより、何が起きたか分からない箇所の修正を優先し、最も重い1〜2本を改稿して同じ6点で再読する。語感の好みだけで良い既刊を変えない。一文要約と修正結果は既存のタスク結果へ、残る未完了だけを既存の引き継ぎへ残す。改稿に伴う画像・字幕の整合、CI、本番確認は共通の公開手順に従う。
- **週次編集**は`clarity_digest.py --days 7`と`--full-text`で7日分の傾向を確認する。初見理解のfailが3本以上、または同じ弱点が2日以上ならドリフトとして翌週の変更1点の優先候補にする。日次・週次とも採否は同じ「公開前の6点」を使う。
- `DAILY_EDITORIAL_BRIEF.md`は更新日、次の重点一つ、強弱の実例、次に避けること、未完了の引き継ぎだけにする。候補と本人案・採用状態・公開URLは`EDITORIAL_IDEAS.md`へまとめる。同じ恒久規則や日時別改善節を重ねず、履歴はPR・コミットに残す。
- 発行の引き継ぎは[DAILY_EDITORIAL_BRIEF.md](DAILY_EDITORIAL_BRIEF.md)の既存欄だけを上書きする。古ければ実際の既刊・本番状態を優先し、次の公開物を含むPRか日次編集の通常更新で追いつかせる。別文書へ同じ次枠メモを複製せず、公開確認だけのdocs-only PRは作らない。

### 実測の読み方

日次は`analytics/daily/`の前日JSTの`daily_page_views`を主指標にする。coverageが`partial`なら途中開始、`unmeasured`や項目欠落は未計測であり、0や一日分の実績にしない。PVは表示回数で、実人数・読了・満足度・面白さの証明ではない。

記事比較には取得時点の`page_views_last_7_days`と対象期間、公開後の経過時間、流入元、サンプル数を添える。`page_views_per_hour`は補助で、`continuation_share`も別記事へ進んだ粗い回遊指標に留める。`daily_visitors / daily_article_reads / visitors_cumulative`をPVへ換算せず、おすすめ順にも使わない。未記録記事のレーン・トーンを推測で後付け分類しない。

2026-11-05 20:00 JST以降のスナップショットでは`published_editorial_metadata_tracked / published_editorial_lanes / published_editorial_tones`と各記事の分類を使える。各群3本未満なら事例として扱い、優劣を断定しない。週次は実文・本人の評価・取得できた反応を分け、翌週に変えることを一つに絞る。自己採点や少数のPVだけで勝ち型を確定しない。

### 題材を枯らさず、既刊を使う

- 日次の候補3〜5件では政策発表と新製品発表の材料を先に確保し、前日の主題・主役の役割・活動・舞台を一文要約で比較する。生活体験が続いた翌日は、産業・科学・インフラ・政策判断・競技・文化制作など最近薄い実題材の一次資料も探し、候補全件を買い物・家庭・近所・個人の利用体験へ戻さない。生活・文化の案も残せるが、主題・行動・結果が違う案を比べる。新しい分類欄・本数ノルマ・台帳は作らず、枠ごとの比較・見送りは冒頭の一度の手順にまとめる。
- 既刊は同じ本文・設定・オチを再発行する在庫ではない。今も使える矛盾、別人物・別場面、関連記事への自然な導線を探す。必要な既刊だけ検索し、全件の手作業再読を各枠へ戻さない。
- **再浮上**は公開日を動かさず今も読める理由を確認する。**派生**は主役・行動・結果などが複数変わり、元記事を知らなくても成立する新作に限る。**続報**は「続報を出すとき」の上限と新しい現実の事実を守る。**関連記事導線**は既存の持続的タグと生成機能を使い、回遊だけのタグや古い記事の固定は足さない。
- 日次の3〜5候補に過去記事由来を混ぜるのは強い時だけ最大1件。元記事・使い方・今回新しくなる点を短く残す。高PVだから続編にせず、現実側の新展開がないなら続報と呼ばない。
- 週次は7日分の新作だけでなく、再び読まれた既刊や記事間移動も見る。残り続ける矛盾・人物・入口を最大2点だけ候補探しへ戻し、新たな再掲レーンや本数ノルマは作らない。

この運用は外部LLM API、新しいGitHub Actionsトリガー、追加DB、有料データ、追加クレジットを必要としない。レーン等の警告は助言、公開カテゴリ・形式・出典・重複などの必須条件は既存CIで検証する。
