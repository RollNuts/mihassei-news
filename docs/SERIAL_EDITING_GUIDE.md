# 未発生新聞｜連載の編集方針（競合・読者調査から）

2026-11-03 時点の公開調査を参照した編集判断。**この調査は当サイトの実際の流入・好みを示すものではない**。各話の文章・安全性・公開の確認を優先し、管理画面や読者ツールの追加は原則しない。

## 参照した市場の状況
- インプレス総合研究所『電子書籍ビジネス調査報告書2026』: ウェブ小説の利用率16.5%（調査対象のモバイル利用者）。無料電子書籍のみ利用28.5%。数字は出版全体の傾向で、未発生新聞の潜在市場規模ではない。https://research.impress.co.jp/report/list/ebook/502499
- カクヨムのミステリーランキング: 多数の長編・連作短編が更新され、読者はあらすじ・話数・第1話の入口から作品を比較できる。ランキング上位だから特定の表現が有効という因果は主張しない。https://kakuyomu.jp/rankings/mystery/yearly?work_variation=all
- 楽天証券『行動ファイナンス研究レポート2026』: 回答者26,534人の情報源では自己判断35.4%、ブログ・動画等の無料情報24.1%。回答者属性は偏りがあるため、投資家全体の代表値や当サイトの読者像としない。https://www.rakuten-sec.co.jp/web/learn/report/2026/survey/
- 株探には適時開示・決算速報・個別銘柄ページなどの大規模な提供機能がある。速報で模倣競争せず、予想条件の事前固定と結果検証で差別化する。https://info.kabutan.jp/about/

## 未発生事件簿：つまらないなら発行しない

**現行の第1話を読んだ編集上の反省：**「翌日付の死亡届」「消された受付番号」「本人の筆跡」という着想には可能性がある一方、書類の説明に比べて登場人物の具体的な行動・葛藤が薄い。終盤も通話の途切れで引くだけになっており、同型を繰り返すと、伏線の多さだけが残って物語が進まない。次回からここを改善する。公開済み第1話自体は履歴保護のため無言で改稿しない。

- **原稿作成前に筋を決める。** 今回、読者の理解がどう変わり、誰が何を失いかけ、登場人物がどんな取り返しのつかない選択をするかを考える。犯人当てゲームより人間の切実さと異変を優先する。嘘、隠し事、見栄、恐れ、守りたい相手などの動機は抽象語で説明せず行動に現す。
- **各話に読後の変化を残す。** 新しい謎を足すだけでは不十分。前の疑問に進展・小さな答え・意外な反転を与え、人物関係か事態が変わる。何も起きない説明回を作らない。驚きは公平な手掛かりから逆算し、解決前の情報の出し惜しみで引っ張らない。
- **不採用になりやすい手癖を避ける。** 書類や時刻の羅列、捜査官が仮説を解説する長台詞、事件ではなく登場人物が頭の中で考えるだけの場面、急な電話・新しい声・意味深な一言だけで終わる回、専門語や設定の後出し、全員が同じ口調で話す会話、毎回同じ章立て。章数・字数を一律固定しない。
- **説明より場面。** 冒頭に独特の光景、対立、ためらい、失敗などを置く。誰が何を望んでいるか、危険を冒してまでその選択をする理由、結果として何を失うかを読者が感じられるようにする。被害予告を受けた人物を単なる謎解きの駒にしない。
- **公開前に最低1回、大きく改稿する。** 自分で反証するように再読。「この回を飛ばしても筋が変わらない」「読後に何も分からない」「同じ電話切断や不穏な余韻だけ」「答えが作者の新設定にしかない」なら構成から再執筆。自動採点やチェック項目を埋めるだけで合格にしない。再執筆しても弱ければその回の発行は見送る。対象をずらしてでも毎回出す方針は**架空ニュースの毎日発行に限定**し、小説には適用しない。
- **初めての人は第1話から。** 既読者には続きから読む導線を用意。読者メモ・強制クイズ・新たな会員機能は追加しない。内部の `clues` と `reader_prompt` は公平性点検に使い、記事末尾の振り返りは必要な人だけ開く。
- **既刊の全話を読む。** 人物・日時・筆跡・受付番号・旧館三階・手掛かり・知っている人物が誰かを照合。第1話の違和感を「実は未来が分かっていた」等の唐突な万能設定だけで説明しない。解決は伏線と人物の選択に結び付ける。既公開話を後出しで書き換えない。

## 未来相場観測室：的中の宣伝より検証
- 速報・ランキング・株価データの大量再配信を狙わず、**仮説→根拠→反証→期限付き判定→振り返り**の一本を深く書く。
- 既出の第1回の明電舎・SWCC・GSユアサ対TOPIXの予測条件・起点日・期日を尊重し、結果が出る前に勝手に変更しない。
- 一次資料（決算短信、決算説明資料、適時開示、官公庁、取引所等）を公開時点で実際に確認し、リンクと確認日を示す。株価・受注・利益率・PER等が取れない場合は**未確認**と書き、数字を補完しない。
- **需要増加≠利益増加≠株価割安**を区別する。銘柄・業種の強気/中立/弱気シナリオと、各シナリオに移る条件を具体化する。
- 最低限、対象・方向または判定条件・比較基準・時間軸・測定方法・反証要因・判定日を事前に記録する。取得できるときは比較の元データと終値も記す。
- 期日到来後の実績で結果を判定し、一次資料などの確認可能な証拠にリンクする。**検証不能は未検証**、結果欄のみ追記してもとの予測は変えない。成績は十分な標本が揃うまで誇張しない。

## 運用と評価
- 自動連載タスクは、GitHub mainの最新版と公開済み全話を確認→新エピソードを追記→テスト/履歴保護→PR→CI成功→main統合→実際の公開URLとrevisionを確認。失敗時は掲載済み扱いにしない。
- `scripts/guard_serial_history.py` が過去の小説本文改稿・予測方法の書換え・検証済み結果の後出し変更を防ぐ。正当な訂正が必要な場合は、過去を無言で消さず訂正文や新しい回で説明する。
- 既存の匿名計測から確認できる連載への回遊や再訪は観察するが、**計測されていない読了率・PV・人間の数・投資成績を作らない**。読者の声や実測が増えた場合だけ導線や文量を再評価する。
- 運営追加費は0円固定。API従量課金・GPT追加クレジット・有料GPU/広告/データ取得をしない。文章内容の質が上がらない新機能は後回し。
