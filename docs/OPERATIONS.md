# 運用の入口

対象は [未発生新聞](https://veripsa.com) と `RollNuts/mihassei-news`。各タスクはこの共通手順と担当分の資料を読み、同じ規則をプロンプトへ複製しない。改善履歴はPR・コミットに残す。

## 担当と正本

時刻はJSTの予定枠。実際の有効状態・時刻はAutomations、機械処理はワークフローと設定JSONを確認する。実行遅延があるため、時刻をずらすだけでは重複を防げない。

朝のメモは日次編集、次枠の2行は発行、次週方針は週次編集が更新する。候補の採用済みURLは公開を確認してから更新する。他担当の引き継ぎを上書きせず、正常な箇所を毎回改稿しない。

## 着手と公開

1. 最新main、`AGENTS.md`、自分と関連担当の直近結果、未統合PR・実行中CIを確認する。前回の未完了作業を先に片付け、同じ記事・ファイルの重複PRを作らない。
2. 発行は予定枠のJST日時と既刊・PRを照合する。遅延や再試行を別枠として二重発行しない。改稿はslug・出典・元資料の日付・架空日・初回公開日時を保持し、`modified_at`だけ実際の更新日時にする。
3. 専用ブランチで必要な変更と回帰検証を行い、PRの最新headのCI・履歴保護を通す。統合直前に最新mainと並行変更を再確認し、安全なら統合する。失敗の無視、強制統合、force push、テスト無効化はしない。
4. 本番revisionと対象URL・画像等の実配信を照合する。PR作成、CI成功、main統合、実配信を区別し、未反映は既存権限で原因を調べる。静的プレビューのAPI未接続を本番障害としない。
5. 読み取り検証か `?analytics=off` を使い、確認操作を読者のPVとして成果に含めない。画面・実画像を見られなければ未目視と記す。

公開する内容がない点検では、理由を短く残して終了する。PR数、規則の追記数、生成数、同じ障害の再報告を成果にしない。

## 画像・動画の担当を重ねない

- 発行・改稿担当は**自分が今回変更した記事**の画像と選抜字幕を確認する。ほかの記事の検品在庫を各発行枠で毎回取り直さない。
- サイト日次担当が残る未検品・差し替え画像を処理する。週次担当は全体の不一致と再発を点検する。現在の記事SHA・画像SHAに一致するacceptedは、新しい不具合がなければ再承認しない。
- 目視採用・不合格の記録は `VISUAL_OPERATIONS.md`、動画のplanと待ち理由は `MOTION_CLIPS.md` に従う。未生成・未検品・不合格は区別し、画像/動画待ちでも合う代替画像で記事を発行する。
- 未解決時だけ `slug／待ち理由／次の作業と担当` を既存結果へ残す。生成0件・idle・skipped、OFFの空一覧、生成済み、本番配信済みを同じ成功にしない。旧画像の指紋・seed・reviewを書き換えて待ちを解消しない。

## 維持する境界

- 追加費用0円。有料AI・画像・動画API、GPU、追加クレジット、有料データ、広告、新規従量課金、有料プラン変更はしない。
- 記事の既存9枠、承認済みX配信、既刊、正史、予測条件、読者データを維持する。担当外の投稿・予約・台帳・他タスク・実行時刻・OFF設定を変更しない。停止中の漫画・旧シュールネタ・ネタ画像を再開しない。
- Macの稼働は実機の状態で確認する。コードや設定済みというだけで稼働と断定せず、停止・負荷・容量保護を解除しない。
- PVは表示回数。匿名ブラウザ数・実人数・読了・面白さ・Xインプレッションとは別。時点・対象期間・経過時間・単位を添え、未取得や計測開始日の一部を0や一日分にしない。少数データから改善の因果、収益、ファン獲得を断定しない。
- 読者画面は読む・探す・保存する・共有するための情報に絞る。内部手順、改善宣言、自己採点、運営者向け説明を載せない。創作表示、出典、必要な計測・保存説明は適切な案内ページに短く残す。

## 結果の残し方

「実際の問題／変更または変更不要／PR・検証と本番状態／次の作業」を短く報告する。Xは原稿登録・予約受付IDと予定時刻・実公開URLを区別する。取得不能な状態を埋めず、同じ保留の全文を毎回繰り返さない。新しいログや管理機能を増やす前に、既存の引き継ぎ・台帳で足りるか確認する。
