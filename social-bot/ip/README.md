# ネジまち — シリーズ設定原本 / IP bible v1.0

> **公式設定の唯一の参照元は** `canon.json`。**各回で確定した出来事の履歴は** `ledger.json`。本文・コマ割りは `../posts.json`。このファイルは人間向けの運用方針であり、JSONの内容が優先する。

## 作品の芯

- ブランド：**ネジまち**（旧「どうでもいい世界」内の独立連載。XのVeripsaアカウントで試験的に配信）
- 合言葉：**巨大な機械の下で、小さな暮らしをしています。**
- 主題：おかしなルールだらけの都市に、善良で小さい住人たちが真面目に暮らしている。
- 読後感：6割くすっと笑える、3割愛嬌、1割切なさ。誰かの弱さを笑う話にはしない。
- **笑われる対象はルールの不合理さであり、住人ではない。** 頑張る住人の小さな優しさを残す。
- 美術：廃工場や青銅管の光る立体都市を背景にした、**オリジナルの幾何学的キャラクター**。銅色の欠けた六角・淡青の一つ目液晶・淡紫の蒸気。親しみやすさ以外の既存キャラクターの意匠、顔立ち、特徴的セリフは真似ない。
- 公開名「ネジまち」は暫定ブランド名。正式な商標・意匠・既存作品の名称確認をしないまま商品化しない。

## 世界のルール（確定）

**舞台：トルマ市・六番配管街。** 道の上には配管と天井灯、巨大な機械の音がある。本物の空は見えず、その向こうが何かはまだ分からない。中央塔の機械が毎日の区分札を発行する。しかし誰が街の規則を作るのか、住人はまだ知らない。

**禁則：紙札は行政上の区分だけ。** 朝の札が無くても時間は流れる。青色灯を点ければ市役所はそれを青空と呼ぶが、本物の空が現れたことにはならない。無許可の親切は「認めない」と言われても、手を差し伸べる行為そのものは止められない。

### 主要キャラクターの不変要素

- **ネジ**：左上が欠けた銅色の六角頭。右に小ネジ1本。紺の作業着に黄色い短いマフラー。細かい修理が得意、素直、最後は誰かのために動く。
- **ピト**：横長の淡青の浮遊液晶端末。**目は一つ**。丁寧に規則を読み上げるが**規則を決められない**。悪役でも万能解説者でもない。
- **モク**：薄紫で少し角のある蒸気生物。橙の手袋と小さい靴。修理を手伝う。**第3話が読者の前での初登場**。煙に変わって消える等の能力は未設定。

### 物語の時系列

| 話 | いつ | どこ | 取り返しのつかない事実 |
|---|---|---|---|
| 第1話「朝の配給」 | D1 7:05 | 朝の配給所 | 朝の受付は7:03に閉まったが、時間は普通に過ぎた |
| 第2話「青空の品質」 | D1 昼前 | 昼灯の広場 | 青色灯を点けることを市は青空と呼ぶ。本物の空は未確認 |
| 第3話「親切の申請」 | D1 午後 | 共同整備台 | 親切は事前申請という条文があるが、ネジはモクを助けた |

## 漫画形式（4コマ固定ではない）

- 2〜6コマ。**オチ・情緒・展開に必要な枚数だけ使う。** 人物の見せ場がない話は無理に4等分しない。
- 1話で状況が分かり、初見でも笑える。長編の謎は通奏低音として少しずつ出す。
- 読者が1秒で分かる1コマ目、ズレが増える中盤、独創的な4秒後のオチ。
- 説明で終わらず、表情・間・道具・街の大きさを使う。コマの繰返しは極力避ける。
- スマホ縦画面1080×1350px、2MB未満PNG、Pillow＋無料日本語フォント使用。
- 画像AI・GPTの有料従量APIを**一切呼び出さない**。既存のコード描画も「完全自動でプロの漫画家の作画」と同等ではなく、改善が必要な粗いパイロット版。

## 後から辻褄を崩さない投稿プロトコル

1. **執筆前** `canon.json`、`ledger.json`、既存の `posts.json`、`state.json` を全件読む。
2. **公開済みは絶対に書き換えない。** `state.json` に予約・公開のある話を変更しない。発見した矛盾は今後のエピソードで説明するか、破綻が大きければ停止して人間に相談する。
3. **新しい確定事実**は `canon.json/facts` に `introduced_in` を明記。必ず同じ話の `ledger.json/entries[].established` と `posts.json/..canon_refs` に入れる。
4. **曖昧にする事実**は `open_mysteries` で管理。早期ネタバレしない。メモにない人格、機械の意識、街の外などを勝手に確定しない。
5. **進行順**は episode 連番、day D1, D2... と order 連番。未来の事実を先の話で参照してはいけない。
6. **PR検証**：`render.py`、`render_ip.py`、`validate.py` の順に実行。`ip/audit.py` が新旧の食い違いを検出したら投稿を停止。絵と脚本の面白さは機械では保証できないので、運用時の編集者チェックは別途必要。
7. **Queue履歴**：新しい話は投稿予約時に本文・コマ・設定のSHA256を保存。後の変更なら自動的に失敗して保護する。
8. 定期的に反応と読みやすさを見て、表現や絵を改善。ただし確定設定・既出の事実の改変と、企画書だけの改訂を混同しない。

### 変更できる / できない

| 変更可能 | 変更禁止（手続きなし） |
|---|---|
| 未来のネタ、コマの数、表情、セリフ、配色の微調整 | 既に配信した話の本文、世界法則の否定 |
| 新キャラ、新しい街区、既出ルールの追加解釈 | ピトの権限やキャラの初登場時期の変更 |
| 未公開の話の修正 | 物語の謎の早すぎる確定、既存作品の意匠の流用 |

## 公開・コスト

旧ネタ15本はアーカイブとして残し、新しい投稿予約対象は **`series=nejimachi` の話だけ** とする。ただし既にBufferへ予約した旧ネタ2本（宇宙人・流れ星）は意図せず消さず、その後に連載を開始する。Xでの公開を確認するまでは「公開済み」と断言しない。

GitHub公開リポジトリの標準Actions / Buffer無料キュー / Pillowで運営。従量課金APIは禁止。運用費が0円のまま成立する範囲を維持し、無料プランの限度変更があれば投稿停止を優先する。

**監査の限界**：JSONの設定ID・時系列・前提条件・投稿後の改変は機械的に検出可能。自然言語の微妙なニュアンスや隠れた矛盾、著作権・商標の完全な適合を自動判定することはできない。毎回の編集確認と記録を併用する。
