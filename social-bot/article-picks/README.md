# 読まれた記事をXへ紹介する

記事紹介は`article-picks/config.json.enabled`で管理する独立した経路。現在は有効で、既存のBuffer Freeチャンネルと送信の共有排他を使う。日次の独自稿`useful`、停止中の旧実験・漫画との役割は[X共通運用](../README.md)を参照する。

## 候補と配信

[`x-original-experiments.yml`](../../.github/workflows/x-original-experiments.yml)が毎日00:05・08:05・16:05頃（JST）に候補を判定する。記事紹介はBufferの`addToQueue`で予約し、公開時刻はチャンネルの実設定に従う。旧実験の停止中は短文を9件まで補充する運用ではなく、`useful`と既存予約を含む共有キューの空き・配信条件を確認する。記事紹介は1日最大3本・1回最大1本・最低6時間間隔。記事紹介側の共有キュー上限は9件にして、10件目は`useful`等の別レーンへ残す。

- 候補は2段階。**新着レーン**は公開2〜18時間の未紹介記事をPV未蓄積でも候補にし、`followup_of`を持つ続報を優先、その次に新しい記事を選ぶ。**実測レーン**は公開12時間以上・21日以内から、サイトと同じ`/api/engagement`の実測PVで選ぶ。JSTの当日を含む直近7日分の`last7DaysPageViews`、当日PV、実際の公開日時の降順。匿名ブラウザ数・いいね・累積PV・X表示回数を順位へ混ぜない。
- 実測レーンは対象期間PVが`min_page_views: 8`以上。新着レーンはPVを条件にしない。どちらも同じ記事slugは一度しか自動紹介しない。閾値や新着扱いは配信条件であり、実人数や面白さの証明にしない。`config.json`と`dispatch.py`を正本とする。
- 全候補を20件ずつGETし、計測開始日時・JST期間・実測日数・期間の完全性が一致することを確認する。計測開始直後は取得済みの期間だけで選び、7日分の完全な実測と扱わない。欠損・不整合・API異常を0や旧指標で補わず、見送る。キュー満杯・配信間隔・独自稿優先の条件も維持する。
- PVの除外条件はサイト側の計測に従う。運用確認の`?analytics=off`、ブラウザの計測無効設定、検出された自動操作・既知bot・prefetchを除外する。過去の閲覧から運用者を推計して引いた数値ではない。
- 本文は通常記事が `【未発生新聞】`、続報が `【続報｜未発生新聞】`、見出し、正規の記事URL。記事側で公開済みの話題タグから先頭2個までを同じハッシュタグとして再利用し、X用に別の流行語を足さない。「創作」「架空」「フィクション」の定型注記を毎回付けず、媒体の説明はリンク先の編集方針・記事ページに任せる。未確認の「大人気」「1位」は付けない。自動画像添付はなく、リンクのOGPはサイトの公開画像を使う。災害・戦争・武力衝突・テロ・大量死傷事故に該当する記事は自動記事紹介から除外し、必要なら人間判断の手動投稿だけで扱う。

## 重複防止と確認

独自稿との共存判定は旧実験の台帳に加え、`useful`の確定受付ID・同一チャンネル・本文SHA・現在の予約本文が一致する予約も認識する。送信前intent、不明な応答、別アカウントや無関係の予約は、この条件を満たしたことにしない。

`state.json`に記事slug・Buffer受理ID・送信時の本文指紋・PV・計測期間と開始日時・実測日数・期間の完全性を保存する。同じ記事は見出しが変わっても再紹介しない。保存が中断した場合はBufferの`scheduled/sent`にある正規記事URLと照合して回復し、台帳を消して再送しない。Bufferを経由しない手動投稿や短縮URLは自動照合できない場合がある。

記事紹介workflow・`state.json`・現在のBuffer予約を照合する。Buffer受付と、Xの実公開URL・本文・表示回数は分ける。旧experimentsの日次監査は記事紹介を網羅しない。実公開や反応を確認できなければ未確認とし、アクセス数の水増し・自動いいね・フォローで補わない。

## 停止の対象

停止を依頼された場合は、対象に対応するフラグだけを変更する。停止操作を確認目的の再送や予約削除と組み合わせない。

| 対象 | 停止する入口 |
| --- | --- |
| 記事紹介のみ | `article-picks/config.json.enabled: false` |
| 独自稿`useful`のみ | `useful-posts.json.enabled: false` |
| 旧実験 | `experiments/config.json.experiment_publishing_enabled: false`（現在停止中） |
| 漫画 | `ip/publication_quality_gate.json.new_reservations_enabled: false`と漫画workflowの停止（現在停止中） |

**全Xの新規自動送信・予約を止める場合は、上の各経路を確認する。** 共有の旧実験workflowだけを止めても別workflowの`useful`は止まらない。既存のBuffer予約はどのフラグでも自動取消しされないため、実予約の扱いは依頼の範囲と配信状況に沿って別に確認する。送信済み・予約済みの本文、画像、ID、台帳を勝手に変更しない。

追加費用0円。既存の無料Buffer・公開GitHub Actionsを使い、外部AI API、X有料API、有料プラン、追加クレジットや広告を導入しない。
