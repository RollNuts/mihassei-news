# 未発生新聞の記事をXへ自動紹介する

Xの自動投稿はこの`article-picks`経路だけを使う。旧シュール短文、キャラ日常、`useful`独自稿、漫画は自動送信しない。既存のBuffer FreeチャンネルとGitHub Actionsだけを使い、追加費用は0円を維持する。

## 配信

[`x-original-experiments.yml`](../../.github/workflows/x-original-experiments.yml)は毎日09:05・11:05・13:05・15:05・17:05・19:05・21:05頃（JST）のcronを基本に候補を判定する。加えて、09:00〜21:59 JSTに`content/articles.json`がmainへ公開されたpushも補助トリガーにする。07:30・23:30枠の公開pushはBufferを読まず書かず終了する。cronはバックアップとして維持し、どちらから起動しても1回最大1本、JST1日最大7本、09:05・11:05・13:05・15:05・17:05・19:05・21:05の**論理7枠につき1本まで**、slug重複防止を同じコードで適用する。GitHub Actionsが遅れて09:05枠の処理が09:36になっても、その受付時刻からさらに2時間待つのではなく、11:05枠は別枠として判定する。同じ論理枠内のcron・公開push重複だけを止める。選ばれた記事はBufferの`shareNow`でその枠の実行時に即時送信を依頼し、一般のBufferキュー待ちで数時間後ろへ流さない。Bufferで観測できる当日の送信・予約が7本に達した場合も追加しない。既存キューは重複・上限確認のため読み取るが、記事紹介そのものはキューの空き時刻に依存しない。

- **新着レーン**: 公開1〜18時間の未紹介記事。続報を優先し、その次に新しい記事を選ぶ。PV蓄積前でも対象にする。新着候補を先に重複・上限・安全性で判定し、成熟記事のPV APIが取得できなくても新着紹介を妨げない。
- **Xでの初見理解ゲート**: 新着・実測PVのどちらも、見出しと既存summaryを読んで状況が自立して伝わる記事だけを紹介する。見出し・要約が欠落/極端に短い、書き出しが「この件」「例の」「これを受け」等の文脈依存、または記事に`x_promotion_skip: true`の編集判断がある場合は候補から除外する。機械的な短文チェックだけで面白さを判定したと見なさず、執筆段階の[`初見読者の理解ゲート`](../../docs/EDITORIAL_LOOP.md#初見読者の理解ゲート)を優先する。Xで長文解説を追加して救済しない。
- **話題の偏り防止**: 続報でない通常記事は、当日すでに自動紹介した記事の先頭タグと重ならない候補が上位3件にあればそちらを優先する。候補がなければ元の順位を使い、投稿本数を減らさない。続報は同じ話題を追うこと自体に意味があるため優先を維持する。
- **実測レーン**: 公開12時間以上・21日以内から、サイトと同じ`/api/engagement`の実測PVで選ぶ。直近7日PV、当日PV、実際の公開日時の順で比較する。
- 同じslugは一度しか自動紹介しない。Bufferのscheduled/sentから正規記事URLを回収して重複送信を防ぐ。
- 災害・戦争・武力衝突・テロ・大量死傷事故に該当する記事は自動紹介しない。
- 本文は通常記事が`【未発生新聞】`、続報が`【続報｜未発生新聞】`、見出し、入る場合は既存summaryからの短い1行、記事側の先頭2タグ、追跡付き記事URL。summaryはタグとURLの文字数を先に確保した残りだけ使い、短すぎる断片は載せない。毎回の「創作」「架空」「フィクション」定型注記は付けない。
- 自動画像添付は行わず、リンク先OGPの公開画像を使う。記事URLには `utm_source=x&utm_medium=social&utm_campaign=article_auto` を付け、サイト既存の匿名・粗粒度な流入計測でX経由を取りこぼしにくくする。完全な参照URLや個人情報は保存しない。

## 発行本数との関係

サイト側は07:30〜23:30の9枠を維持し、通常は1日7〜9本の新作公開を目標にする。Xはその全記事を必ず流すノルマではない。重複、危機ニュース、品質、論理枠の使用済み、当日7本上限により見送る場合がある。Actionsの開始遅延だけを理由に次の2時間枠まで潰さない。弱い記事や古い記事でX枠を埋めない。

## 確認

23:45 JSTの`x-delivery-audit.yml`は`article-picks/state.json`の直近7日分を読み、保存済みBuffer IDと正規記事URLをscheduled/sentの現在値へ照合する。定時起動の欠落に備え、21:00〜23:59 JSTの`content/articles.json`公開pushでも同じ読み取り専用監査を補助起動する。昼間の公開pushはテストのみでBufferを読まない。結果は既存の`article-picks/delivery.json`へ保存する。再送・予約編集・X投稿は行わない。

`state.json`に記事slug、Buffer受理ID、本文指紋、選定根拠、必要なPV期間、`slot_jst`、`submission_mode: shareNow`を保存する。移行前の受理記録は`queued_at_utc`から論理枠を推定する。Bufferの即時送信受付はX実公開の独立確認ではないため、provider上のsentとX実公開を分けて確認し、未確認の公開や反応を0扱いしない。台帳を削除して同じ記事を再送しない。

停止は`article-picks/config.json.enabled: false`だけで行う。旧自動レーンは停止状態を維持し、本人の明示的な再開依頼なしに有効化しない。
