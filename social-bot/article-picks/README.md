# 未発生新聞の記事をXへ自動紹介する

Xの自動投稿はこの`article-picks`経路だけを使う。旧シュール短文、キャラ日常、`useful`独自稿、漫画は自動送信しない。既存のBuffer FreeチャンネルとGitHub Actionsだけを使い、追加費用は0円を維持する。

## 配信

[`x-original-experiments.yml`](../../.github/workflows/x-original-experiments.yml)が毎日09:05・11:05・13:05・15:05・17:05・19:05・21:05頃（JST）に候補を判定する。1回最大1本、JST1日最大7本、記事紹介同士は最低2時間間隔。Bufferで観測できる当日の送信・予約が7本に達した場合も追加しない。共有キューは最大10件まで使える。

- **新着レーン**: 公開1〜18時間の未紹介記事。続報を優先し、その次に新しい記事を選ぶ。PV蓄積前でも対象にする。
- **実測レーン**: 公開12時間以上・21日以内から、サイトと同じ`/api/engagement`の実測PVで選ぶ。直近7日PV、当日PV、実際の公開日時の順で比較する。
- 同じslugは一度しか自動紹介しない。Bufferのscheduled/sentから正規記事URLを回収して重複送信を防ぐ。
- 災害・戦争・武力衝突・テロ・大量死傷事故に該当する記事は自動紹介しない。
- 本文は通常記事が`【未発生新聞】`、続報が`【続報｜未発生新聞】`、見出し、記事側の先頭2タグ、正規URL。毎回の「創作」「架空」「フィクション」定型注記は付けない。
- 自動画像添付は行わず、リンク先OGPの公開画像を使う。記事URLには `utm_source=x&utm_medium=social&utm_campaign=article_auto` を付け、サイト既存の匿名・粗粒度な流入計測でX経由を取りこぼしにくくする。完全な参照URLや個人情報は保存しない。

## 発行本数との関係

サイト側は07:30〜23:30の9枠を維持し、通常は1日7〜9本の新作公開を目標にする。Xはその全記事を必ず流すノルマではない。重複、危機ニュース、品質、配信間隔、当日7本上限により見送る場合がある。弱い記事や古い記事でX枠を埋めない。

## 確認

23:45 JSTの`x-delivery-audit.yml`は`article-picks/state.json`の直近7日分を読み、保存済みBuffer IDと正規記事URLをscheduled/sentの現在値へ照合する。結果は`article-picks/delivery.json`へ保存する。これは読み取り専用で、再送・予約編集・X投稿は行わない。

`state.json`に記事slug、Buffer受理ID、本文指紋、選定根拠、必要なPV期間を保存する。Buffer受付とX実公開は別状態として扱い、確認できない公開や反応を0扱いしない。台帳を削除して同じ記事を再送しない。

停止は`article-picks/config.json.enabled: false`だけで行う。旧自動レーンは停止状態を維持し、本人の明示的な再開依頼なしに有効化しない。
