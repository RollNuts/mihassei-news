# 停止中のX実験と配信記録

旧シュール短文・キャラ日常・ネタ画像の新規制作と予約は退役済み。`config.json`の`experiment_publishing_enabled`、`launch_first_visual_now`、`two_daily_midday_enabled`はすべて`false`。以前の「7枠を補充」「21〜28本を常備」「画像を交互に投稿」は現行の制作指示ではない。自動X投稿は記事紹介だけで、再開には本人の新しい明示的な依頼が必要。

`useful`自動経路も退役済み。[X共通運用](../README.md)を参照。現在の自動送信は[記事紹介](../article-picks/README.md)だけであり、この旧実験ディレクトリは履歴・検証・過去配信の読み取り専用として扱う。

## 保持する記録

| ファイル | 用途 |
| --- | --- |
| `posts.json` | 旧原稿・タグ・画像指定。送信済みの本文やメタデータを改稿しない |
| `state.json` | 原稿/最終本文/画像のSHAとBuffer受理ID。削除・IDの付け替え・再送をしない |
| `delivery.json` | 読み取りで観測した配信状態・予定日時・リンク・観測時刻。現在値と過去のキャッシュを分ける |
| `review.md` | 保存済み記録からの集計。未投稿在庫や過去の仮説は現在の制作ノルマではない |
| `../metrics/records.json` | 取得元と時間窓を確認できた投稿別実測。予約・送信件数から表示回数を作らない |

既存Buffer予約は停止フラグだけでは取り消されない。下書きへ移した漫画や不採用作品を復活させず、既存の本文・画像・正史・承認ゲートを保持する。過去の変更経緯はPR/コミット履歴で確認し、この文書へ実装日記を追記しない。

## 既存予約の読み取り監査

[`x-delivery-audit.yml`](../../.github/workflows/x-delivery-audit.yml)が23:45 JSTに1回、`probe_delivery.py`でこのディレクトリの`posts.json`・`state.json`にあるBuffer IDを確認する。旧実験がOFFで、全保存予約の同一Buffer ID・確認日時付きsent/draftがそろえば、外部API照会とファイル更新を省略する。未確認・scheduledが残れば監査を続ける。**この旧監査は過去実験の履歴確認用で、現行の記事紹介を網羅しない。現行配信監査はarticle-picks側を使う。** 同じ日の確認を増やすための新しい定期処理は作らない。

- 同一Buffer ID・チャンネル・最終本文を照合する。最大20件を10件ずつの2リクエストで読み、成熟した指標は最大1件。失敗時に個別照会を追加して無料API枠を消費しない。
- `scheduled`の`dueAt`はタイムゾーンを含む観測値だけ採用する。欠損時は未取得とし、作成時の受付予定から現在の時刻を推定しない。
- `sent`はBuffer側の状態。Xでの実公開、投稿別インプレッション、報酬対象の指標は別に確認する。過去のpermalinkや指標を保存しても、最新の公開確認にはしない。
- `health.observed_original_sent_by_jst_day`は直近7日、`observed_scheduled_originals_by_jst_day`は観測時から3日分の**部分記録**。欠損を投稿ゼロや7枠未達と断定せず、Bufferの曜日別スケジュールが有効かの証明にも使わない。
- 予定を2時間過ぎた`scheduled`や予定時刻欠損は要確認。反映遅延と投稿失敗を分け、予約編集・削除・再送で診断しない。

旧[`x-delivery-state.yml`](../../.github/workflows/x-delivery-state.yml)には日次・main-pushトリガーがない。新たな二重監査として有効化しない。監査が編集するのは`delivery.json`であり、X投稿や送信台帳ではない。

## 保存済み実測の比較

`review.py`は旧原稿・台帳・配信記録と`../metrics/records.json`をオフラインで比較する。実測投稿IDと`experiment_id`、公開後の観測時間を照合する。タグ・形式・画像有無の比較は各群5件未満なら判定保留。5件以上でも題材・時刻・読者規模の差があり、因果効果とは断定しない。Bufferの初期値0や時間窓未確定の指標を24h/72h実測に置き換えない。

この集計のために新規原稿・画像・タグ実験を補充しない。現在の編集改善はX夜レビューで扱い、必要な履歴だけ参照する。追加費用0円、既存無料経路・API上限・固定アカウント・重複防止を維持する。
